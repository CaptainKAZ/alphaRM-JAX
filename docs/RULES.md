# 1. 这份规则想解决什么

这不是一份“越真实越好”的机器人仿真规则，而是一份**为端到端强化学习服务**的规则。它要保留 RoboMaster 里真正影响战术决策的东西：

- 占点：只有净占点人数为正才得分，逼团队争夺中心；
- 控热：连续开火会过热，必须自己决定什么时候打、什么时候停；
- 掩体：L 形掩体和两条短掩体既挡移动，也挡视线；
- 视野：FOV 只有 90°，云台要转，队友和敌人都会挡视线；
- 小陀螺：用机动性换命中率，既有收益也有代价；
- 复活：死亡不是结束，但复活位置、无敌时间和回血会改变攻防节奏；
- 碰撞风险：高速冲撞直接判负，逼机器人学会“别撞”；
- 信息不对称：敌人血量只能估，命中率不可见，敌人信息不共享。

它**不**模拟：

- 弹丸的飞行、下坠、飞行时间；
- 装甲板的朝向、跳弹、伤害衰减；
- 真实相机的图像、光照、运动模糊；
- 英雄、重装、哨兵、工程、飞镖；
- 金币、弹药量、兑换、工作台；
- 高地、隧道、高差、跨层视野；
- 裁判系统的黄牌、红牌、读条、异常离线。

如果你要实现的是“视觉端到端”，请把本文档的“观测”换成相机/分割图，但规则层不变。本文档默认使用向量观测。

# 2. 阅读约定与术语

## 2.1 单位与坐标

- 所有长度单位是米（m）。
- 所有时间单位是秒（s）。
- 所有角度在规则描述里用度（°），在公式里用弧度（rad）。
- 场地坐标：原点在场地正中心，x 轴向右，y 轴向上。
- 红方在左上，蓝方在右下；把红方整体绕原点旋转 180° 就得到蓝方。
- 机器人位置指“机器人碰撞圆的圆心”，不是车身某个角。
- 机器人朝向指“云台/枪口的朝向”，不是底盘朝向。底盘没有朝向。

## 2.2 “帧”和“tick”

本文的“帧”等于一次决策 + 一次物理推进，长度固定为：

```text
dt = 0.1 s
```

一局 180 s，所以一局固定 **1800 帧**。帧号从 1 到 1800。第 k 帧开始时，策略看到的是第 k-1 帧结束时的观测；第 k 帧的动作在第 k 帧内生效。

## 2.3 队伍与机器人编号

- 每队 3 台机器人，红方 3 台，蓝方 3 台，共 6 台。
- 6 台机器人完全同构：血量、速度、加速度、云台、热量、伤害都一样。
- 红方内部编号 1、2、3；蓝方内部编号 1、2、3。
- 目标选择里的“敌人 1/2/3”是**相对自己队伍**的编号，不是全局编号。
- 固定出生位后，敌人编号与出生槽位绑定，整局不变；复活不会改变编号。

## 2.4 存活、死亡、尸体、无敌

- **存活**：`alive = true` 且 `hp > 0`。只有存活机器人能移动；只有存活且非无敌的机器人能开火、占点；无敌敌人可以被选中/锁定和预瞄，但不能被伤害。
- **死亡**：`hp` 降到 0 或以下的那一帧，机器人从存活变为死亡。
- **尸体**：机器人死亡后进入的 `DEAD` 状态，不是另一个新单位。它保留同一个编号、同一个碰撞圆、同一个遮挡圆，会继续滑动，会挡移动、挡视线，但不能被选为目标、没有血量、不能开火、不占点。
- **无敌**：复活后的一段时间。无敌机器人可以移动、挡视线、回血，但不受弹丸伤害、不能开火、不占点；它可以被选中/锁定和预瞄。

## 2.5 目标锁定与“已经瞄准”

- **锁定**：机器人选择了一个敌人，并且这个敌人当前可见、存活。无敌敌人也可以被锁定和预瞄，只是不能开火命中。锁定后，云台会自动转向它。
- **已经瞄准**：在某一帧开始时，机器人上一帧结束时仍然锁着同一个目标。这个词只是描述“锁定已经建立”，本身不额外改变任何数值；`tau_eff` 每帧随目标当前小陀螺程度连续变化（见 8.8）。如果目标在锁定过程中开始小陀螺，`tau_eff` 会变大，`p_t` 不重置，最终命中率再乘小陀螺系数。
- 锁定不是永久的：目标死亡、离开 90° FOV、被完全遮挡，都会立即丢失锁定；目标进入无敌**不会**丢失锁定，可以继续预瞄。锁定本身没有距离条件，12 m 外仍然可以锁定；角度只有“离开 90° FOV”这一条，1° 是开火条件，不是锁定条件。当前实现额外要求 `dist < 12 m` 才允许选择/锁定，`12 m` 是“能打到的极限”也是目标 mask 的锁定上限。
- **v1.2 口径（目标 mask 立即生效）**：目标选择必须逐帧检查“当前帧可见（`p_vis > 0`）”。一旦目标离开 FOV 或被完全遮挡，本帧就不再允许选择它；上一帧的锁定目标也不例外，不存在“隔着掩体/对着墙继续保持锁定”的例外。锁定丢失后 `p_t = 0`，策略必须靠记忆和移动重新搜索、重新锁定。

## 2.6 小陀螺程度

小陀螺不是一个“开/关”按钮，而是一个 0 到 1 的连续量，记作 `s`：

- `s = 0`：完全没转；
- `s = 1`：完全进入小陀螺；
- 从 0 到 1 需要连续 1.0 s，从 1 到 0 也需要 1.0 s。

**v1.2 口径（连续跟随）**：策略输出的是 0 到 1 的连续目标 `u_spin`，`s` 不再由二值 `spin_cmd` 驱动，而是以固定斜率跟随 `u_spin`：

```text
s_next = clamp(s + clip(u_spin - s, -dt / 1.0, +dt / 1.0), 0, 1)
```

- 输出 1：`s` 用 1.0 s 从 0 爬到 1；
- 输出 0.5：`s` 稳定在 0.5；
- 输出 0：`s` 用 1.0 s 退回 0；
- 每帧最大变化 `dt / 1.0 = 0.1`（`dt = 0.1`）。

后文所有“×0.9”“×0.6”“速度减半”都会乘以这个连续程度，而不是瞬间跳变。

## 2.7 可见弧与最大可见弧

这是本文档里最容易被误解的几何量，先讲清楚。

想象你站在自己的圆心 O，敌人是一个半径 r 的圆，圆心 C，距离 `d = |OC|`。从 O 向敌人的圆作两条切线，切点把敌人的圆周分成两段。朝向你的那一段，就是“理论上能看到的正面弧”。

- **最大可见弧**：两条切线之间的正面弧长，用角度表示。
- **实际可见弧**：这条正面弧里，没有被掩体、其他机器人、尸体挡住的部分。
- **可见比例**：实际可见弧 / 最大可见弧。

最大可见弧的公式是：

```text
full_arc(d) = 2 × arccos(r / d)
```

其中 `arccos` 的结果是弧度。几个关键值：

- 两个圆刚好贴住，`d = 2r`：`full_arc = 120°`；
- 距离 1 m、半径 0.3 m：约 145°；
- 距离 5 m：约 173°；
- 距离 12 m：约 177°；
- 距离越远，越接近 180°，但永远小于 180°。

注意：这不是“敌人在画面里占多大”的角直径。角直径是近大远小；最大可见弧是“敌人圆周正面半圆”的弧长，贴住时 120°，远了接近 180°。两者不是一回事。

## 2.8 命中率、期望伤害、低通

- **命中率**：一发抽象弹丸命中目标的概率，记作 `p`，范围 0 到 1。
- **期望伤害**：不逐发模拟“中/不中”，而是直接造成 `p × 单发伤害`。例如 `p=0.5`、单发 20，则这一发期望造成 10 点伤害。
- **低通**：命中率不是瞬间从 0 跳到理想值，而是每帧向理想值靠近一点，像一个漏水的桶慢慢装满。这个“慢慢”的速度由时间常数 `tau` 决定。
- **收敛值 `p_t`**：当前实际用于伤害计算的命中率。它从 0 开始，按低通逐渐靠近理想命中率。

## 2.9 法向、切向、相对法向速度

- **法向**：垂直于接触面的方向。墙的法向指向场地内部；两个机器人碰撞时，法向是两台机器人圆心连线方向。
- **法向速度**：速度在法向上的分量。只有“朝墙里”“朝对方身上”的那一部分才算危险。
- **切向速度**：沿接触面滑动的速度。擦墙、擦身不算冲撞。
- **相对法向速度**：两台机器人速度差在法向上的分量。两车相向而行时最大，同向同速时为 0。
- **主动方**：在两车碰撞中，自己朝对方方向的法向分量更大的一方。

## 2.10 “2D 全高”掩体

本文所有掩体都是平面上的实心区域，没有高度差异：

- 不能穿过；
- 不能从上面越过；
- 不能从下面钻过；
- 完全阻挡视线；
- 没有“高打低”“低打高”的视野优势。

# 3. 场地

## 3.1 场地外形

场地是一个长方形：

```text
长 12.0 m（x 方向）
宽 8.0 m（y 方向）
```

边界为四面墙：

```text
x = -6.0，x = +6.0
y = -4.0，y = +4.0
```

机器人不能越过墙。机器人的碰撞圆半径是 0.30 m，所以机器人圆心的合法范围是：

```text
x ∈ [-5.70, +5.70]
y ∈ [-3.70, +3.70]
```

如果圆心到达边界，机器人被推回，朝墙的法向速度被清零；如果撞墙的法向速度达到判负阈值，按第 12 节处理。

场地是 180° 中心对称的。红方的每一个几何元素，绕原点旋转 180° 后都能在蓝方找到对应元素。

场地图见：

![平面战场](field_layout_flat.png)

## 3.2 启动区与回血区

每方有一个 2.5 m × 2.5 m 的正方形启动区。这个区域同时是：

- 开局出生区；
- 回血区；
- 没有经济系统，所以没有补弹、兑换、工作台。

红方启动区：

```text
x ∈ [-6.0, -3.5]
y ∈ [1.5, 4.0]
```

蓝方启动区：

```text
x ∈ [3.5, 6.0]
y ∈ [-4.0, -1.5]
```

启动区是回血区：机器人在里面可以按第 11 节回血。回血不需要停下来，不需要面向某个方向。

本文没有“补给禁区”，但对方启动区是**伤害区**：

- 机器人可以进入对方启动区；
- 只有站在**己方**启动区里才能回血；
- 站在**对方**启动区里会持续扣血，速率与回血相同：81.25 HP/s，每帧 8.125；
- 伤害区可以把人打到 0 血，死亡后没有击杀者，不给击杀分；
- 无敌机器人不受这个伤害（无敌仍然免伤害）；无敌结束若还在对方启动区，开始扣；
- 边界算区内：`x = -3.5` 或 `y = 1.5` 这种正好在边线上的点，算在启动区内；
- 这样进攻方最多在泉水外面打人，不能站在泉水里无伤虐泉。

## 3.3 固定出生位

开局时三台机器人固定在三个槽位，不做随机抖动。红方三个槽位：

```text
R1 = (-5.35, 3.30)
R2 = (-5.35, 2.20)
R3 = (-4.50, 2.75)
```

蓝方三个槽位是红方的 180° 旋转：

```text
B1 = ( 5.35, -3.30)
B2 = ( 5.35, -2.20)
B3 = ( 4.50, -2.75)
```

槽位与机器人编号绑定：

- 红方 1 号在 R1，2 号在 R2，3 号在 R3；
- 蓝方 1 号在 B1，2 号在 B2，3 号在 B3。

槽位之间距离大于 0.6 m，机器人半径 0.30 m，所以开局不会重叠。槽位到启动区边缘的距离也大于 0.30 m，不会卡墙。

开局时：

- 血量 = 325；
- 热量 = 0；
- 过热 = 否；
- 小陀螺 = 0；
- 速度 = 0；
- 云台朝向 = 面向场地中心；
- 锁定目标 = 无；
- `p_t = 0`；
- 未无敌、未死亡。

复活时不回到出生槽位，而是回到“复活结算时尸体所在的位置”；具体见第 11 节。

## 3.4 中央占领区

中央占领区是一个圆：

```text
圆心 (0, 0)
半径 R = 1.5 m
```

这个圆是简化的“中央控制区”。官方 2027 的中央控制区是 3 m × 3 m 方形，本文用它的内切圆，面积略小，边界更清晰。

占领判定看机器人圆心：

```text
到原点的距离 <= 1.5 m
```

正好在边界上算圈内。

## 3.5 L 形掩体

原来的两块高地不做了，改成两块 L 形掩体。L 形掩体是 2D 实心区域，厚度 0.20 m，没有高度概念，完全阻挡移动和视线。

### 3.5.1 红方 L 形掩体

红方 L 形掩体由两条矩形组成：

- 竖边：`x ∈ [-3.50, -3.30]`，`y ∈ [-1.00, 3.06]`；
- 横边：`x ∈ [-3.50, -1.50]`，`y ∈ [2.86, 3.06]`。

两条矩形在左上角连在一起，形成一个开口朝右下方的 L。碰撞时按这 6 个顶点组成的**实心并集多边形**处理，不能把两个矩形当成两个独立完整矩形；两个矩形重叠处的内部接缝不是外墙，不能在那里判负。

用多边形顶点按顺序写就是：

```text
(-3.50, -1.00)
(-3.30, -1.00)
(-3.30,  2.86)
(-1.50,  2.86)
(-1.50,  3.06)
(-3.50,  3.06)
```

### 3.5.2 蓝方 L 形掩体

蓝方是红方的 180° 旋转：

- 竖边：`x ∈ [3.30, 3.50]`，`y ∈ [-3.06, 1.00]`；
- 横边：`x ∈ [1.50, 3.50]`，`y ∈ [-3.06, -2.86]`。

多边形顶点：

```text
( 3.50,  1.00)
( 3.30,  1.00)
( 3.30, -2.86)
( 1.50, -2.86)
( 1.50, -3.06)
( 3.50, -3.06)
```

### 3.5.3 L 形掩体的作用

- 机器人不能进入或穿过 L 形区域；
- 视线不能穿过 L 形区域；
- 子弹没有飞行过程，所以“挡住子弹”等价于“挡住视线”；
- 掩体没有高度，不存在“高打低”；
- 掩体边缘不会造成伤害；只有高速撞上去才判负。

## 3.6 两条短掩体（原高垛位置）

原高地内侧的两个“高垛”保留为短掩体。它们是 2D 实心矩形，尺寸 0.15 m × 1.80 m，没有高度概念。

红方短掩体：

```text
x ∈ [-1.65, -1.50]
y ∈ [-0.10, 1.70]
```

蓝方短掩体：

```text
x ∈ [1.50, 1.65]
y ∈ [-1.70, 0.10]
```

这两条短掩体紧贴中央圆的左右边界，但不进入中央圆内部：

- 它们挡移动；
- 它们挡视线；
- 它们不能被穿过；
- 它们不产生占领分；
- 它们不是“高地”，没有上下关系。

## 3.7 场地里没有的东西

本规则明确没有：

- 高地；
- 隧道；
- 工作台；
- 补给区里的兑换；
- 中央控制区的占领进度；
- 高地控制区；
- 经济系统；
- 弹丸补给；
- 英雄/重装/哨兵；
- 飞镖；
- 雷达。

场地里只有：墙、启动/回血区、中央圆、两块 L 形掩体、两条短掩体。

# 4. 机器人本体

## 4.1 同构步兵

双方各 3 台完全同构的步兵机器人。没有角色差异，没有“一号位/二号位”的数值差异。编号只用于目标选择和出生位。

每台机器人有：

- 一个碰撞圆；
- 一个遮挡圆；
- 一个云台朝向；
- 一个血量；
- 一个热量；
- 一个小陀螺程度；
- 一个死亡/复活状态；
- 一个锁定目标；
- 一个命中率收敛值；
- 一个归一化质量 1.0。

质量只用于碰撞推动的计算。因为所有机器人和尸体质量都为 1.0，碰撞修正对双方是对称的；不需要区分“重车/轻车”。

## 4.2 尺寸

机器人用圆近似：

```text
碰撞半径 = 0.30 m
遮挡半径 = 0.35 m
```

- 碰撞半径用于移动、撞墙、撞掩体、撞机器人、撞尸体。
- 遮挡半径用于“机器人挡视线”，比碰撞半径略大，避免擦边看不见。
- 视觉渲染可以用 0.30 m 的圆；规则计算用上面两个半径。

为什么是 0.30 m：2027 机器人制作规范里，步兵最大收纳尺寸是 600 × 600 × 600 mm，最大伸展尺寸是 800 × 800 × 800 mm。0.30 m 半径对应 0.60 m 直径，接近 600 mm 收纳尺寸；0.35 m 遮挡半径是对“方形车身四角”和“云台突出”的折中。不是 0.20 m。

## 4.3 血量

HP 就是“血量”。本文的 HP 是一个连续的数值，不是整数格子。

```text
最大血量 = 325
初始血量 = 325
```

- 内部血量是浮点数，可以出现 287.4 这种值。
- 显示和观测时可以取整，但伤害结算用浮点。
- 观测里的血量归一化到 0 到 1：`hp / 325`。
- 规则本身用绝对血量 325，不用 0 到 1 的“规则血量”；归一化只是给神经网络看的。

## 4.4 移动

机器人是全向移动，没有底盘朝向。它可以在不转身的情况下向任意方向平移。

策略给出一个二维速度意图：

```text
u_v = (u_x, u_y)
```

每个分量范围是 `[-1, 1]`。先裁剪模长：

```text
u_v = u_v / max(1, ||u_v||)
```

然后变成目标速度：

```text
v_des = u_v × v_max_eff
```

其中 `v_max_eff` 是受小陀螺影响后的最大速度。再计算加速度：

```text
a = (v_des - v) / dt
a = clip_norm(a, a_max_eff)
v_next = v + a × dt
v_next = clip_norm(v_next, v_max_eff)
```

规则只定义速度 `v_next`。位置积分由 **VMAS 引擎自带的动力学**完成，不手写 `p_next` 公式；实现时不要再用另一个积分器覆盖 VMAS 的位置更新。

`clip_norm(x, m)` 的意思是：如果向量 x 的长度超过 m，就把它按比例缩短到长度 m；如果没有超过，就不动。

基础参数：

```text
v_max = 3.0 m/s
a_max = 5.0 m/s²
```

小陀螺影响：

```text
v_max_eff = 3.0 × (1 - 0.5 × s)
a_max_eff = 5.0 × (1 - 0.5 × s)
```

所以满小陀螺时，最大速度 1.5 m/s，最大加速度 2.5 m/s²。

机器人死亡时速度不清零，尸体按第 10 节继续滑动。存活机器人被墙/掩体/其他机器人修正位置时，速度按碰撞规则处理。

**v1.2 执行器口径**：实现可以复用 VMAS 的 `VelocityController` 作为底盘执行器，但必须先把目标速度限制成 `v_target = v + clip_norm(v_des - v, a_max_eff × dt)`，再让控制器跟踪 `v_target`，并把输出力夹到 `mass × a_max_eff`、把下一帧速度夹到 `v_max_eff`。如果执行器无法在一个 `dt` 内精确复现本条公式，以本条公式为准（训练/评测走精确路径，PID 只保留给人机大战/渲染）。

## 4.5 云台

云台朝向记作 `ψ`，范围是 `[-180°, +180°)`，可以无限旋转，没有机械限位。

### 手动转向

没有锁定目标时，策略给出一个转向意图 `u_yaw ∈ [-1, 1]`：

```text
ω_manual = u_yaw × 270°/s
```

每帧转：

```text
ψ_next = wrap(ψ + ω_manual × dt)
```

`wrap` 是把角度折回 `[-180°, 180°)`。

### 自动朝向

有锁定目标时，云台自动转向目标，手动转向被忽略。

自动转向不是“瞬间贴脸”，而是每帧最多转 27°：

```text
err = wrap(bearing_to_target - ψ)
step = clip(err, -27°, +27°)
ψ_next = wrap(ψ + step)
```

270°/s × 0.1 s = 27°，所以这就是“最大角速度硬转”，但不允许超调。误差小于 27° 时，本帧直接转到目标方向；不会出现“转过头再转回来”的抖动。

没有角加速度限制，没有云台惯性。

### 云台朝向的用途

`ψ` 只用于：

- 定义 FOV；
- 定义目标是否在视野内；
- 定义开火角误差；
- 渲染枪口方向。

它不影响底盘移动方向。机器人可以一边向左平移，一边把云台转向右边。

## 4.6 小陀螺

### 4.6.1 进入和退出

策略给出一个 0 到 1 的连续目标 `u_spin`：

- `u_spin = 1`：想到达满小陀螺；
- `u_spin = 0.5`：想到达半小陀螺并保持；
- `u_spin = 0`：想退出小陀螺。

小陀螺程度 `s` 按固定斜率跟随目标：

```text
s_next = clamp(s + clip(u_spin - s, -dt / 1.0, +dt / 1.0), 0, 1)
```

因此：

- 从 0 到 1 需要连续 1.0 s；
- 从 1 到 0 也需要 1.0 s；
- 输出 0.5 时，`s` 会在约 0.5 s（5 帧）内从 0（或 1）收敛到 0.5 并保持；
- 中途改变目标，会按同样斜率朝新目标靠拢；
- 死亡时 `s = 0`；
- 复活时 `s = 0`。

### 4.6.2 小陀螺对自己的影响

| 影响 | 公式 | 满小陀螺时 |
|---|---|---:|
| 最大速度 | `3.0 × (1 - 0.5s)` | 1.5 m/s |
| 最大加速度 | `5.0 × (1 - 0.5s)` | 2.5 m/s² |
| 出射命中率上限 | `1.0 × (1 - 0.1s)` | 0.9 |
| 自己的瞄准收敛时间 | 不变 | 不变 |

注意：小陀螺**不**延长自己的瞄准时间。自己转，只影响自己的机动和出射上限。

### 4.6.3 小陀螺对敌人的影响

如果目标在转小陀螺，那么打它的机器人会受到两个影响：

1. **入射命中率乘系数**：

```text
m_spin = 1 - 0.4 × s_target
```

满小陀螺时 `m_spin = 0.6`，即打它的命中率乘 0.6。

2. **瞄准它的收敛时间变长**：

- `tau_eff` 每帧按目标当前 `s_target` 连续计算：`tau_eff = tau × (1 + 0.5 × s_target)`；
- 如果目标在锁定过程中开始转：`tau_eff` 随 `s_target` 增大而变长，`p_t` 不重置；
- 如果目标停止转：`m_spin` 回到 1，`tau_eff` 随 `s_target` 减小而变短，`p_t` 继续。

这里的“最终命中率”指 `p_t × m_spin`。`p_t` 本身仍然按自己的 `tau_eff` 慢慢收敛；`m_spin` 是最后再乘上去的系数。

### 4.6.4 双方都转小陀螺

双方都转时：

- 各自打对方的入射命中率乘 0.6；
- 各自出射上限乘 0.9；
- 各自的 `tau_eff` 最多是 1.5 倍，不叠成 2.25 倍；
- 入射命中率系数 `m_spin = 1 - 0.4 s` 和出射上限 `1.0 (1 - 0.1 s)` 随 `s` 连续变化；
- `tau_eff = tau × (1 + 0.5 × s_target)` 也随目标 `s_target` 连续变化；不会因为双方都转而叠成两次 1.5 倍。

# 5. 一帧里到底发生什么

这一节是整份规则的“判定顺序”。顺序不同，结果会不同，所以必须固定。

每一帧按下面顺序执行：

开局没有倒计时，也没有准备阶段。第 1 帧直接开始，机器人已经在固定出生位，血量 325、热量 0、小陀螺 0、比分 0。第 1800 帧结束后比赛结束。

## 5.1 第一步：读取动作

策略根据上一帧结束时的观测，输出：

- 二维速度意图；
- 云台转向意图；
- 小陀螺意图；
- 目标选择（无 / 敌人1 / 敌人2 / 敌人3）；
- 开火键（0/1，无目标时被 mask）。

第 6 维是独立的开火键（0/1）；目标选择只负责锁定，不再等同于开火。没有锁定目标时开火键会被 mask 掉，具体见第 7 节。

## 5.2 第二步：更新小陀螺程度

按 `u_spin` 连续跟随更新 `s`（`s_next = clamp(s + clip(u_spin - s, -dt/1.0, +dt/1.0), 0, 1)`）。这一帧的移动速度上限、加速度上限、出射上限、目标闪避系数，都用更新后的 `s`。

## 5.3 第三步：移动

存活机器人按 4.4 节的公式算出速度 `v_next`；位置由 VMAS 引擎推进，规则不手写位置积分。

`DEAD` 状态的尸体不响应动作，按下面固定顺序滑动：

1. 读取当前速度 `v`；
2. 如果 `|v| <= 0.5 m/s`，直接令 `v_next = 0`；
3. 否则令 `v_next = v × (|v| - 0.5) / |v|`；
4. 如果 `|v_next| < 0.01 m/s`，再令 `v_next = 0`；
5. 把 `v_next` 交给 VMAS 引擎，由引擎推进位置。

也就是说，尸体在 5.3 先减速、再移动；5.4 的碰撞可以在本帧改变速度，但下一帧仍然先扣 0.5 m/s。死亡当帧不额外减速，从下一帧的 5.3 开始扣。

## 5.4 第四步：碰撞与判负

检查：

- 机器人是否撞墙；
- 机器人是否撞 L 形掩体；
- 机器人是否撞短掩体；
- 机器人是否撞另一个机器人；
- 机器人是否撞尸体；
- 尸体是否撞墙/掩体/机器人。

用碰撞发生前的速度计算“法向速度”和“相对法向速度”。

如果任何一方达到判负阈值：

- 立即结束本局；
- 本帧不再进行感知、锁定、开火、占点、计时；
- 判定见第 12 节。

如果没有达到判负阈值：

- 只做位置分离和速度修正；
- 不扣血；
- 继续后面的步骤。

## 5.5 第五步：几何可见性（只用于选目标，不生成观测）

用 5.3 移动后的位置、**5.7 转向前的当前云台朝向**，计算每个存活敌人的：

- 方位角；
- 是否在 FOV 内；
- 最大可见弧；
- 实际可见弧 `p_vis`；
- 当前是否可见（`p_vis > 0`）。

死亡敌人直接跳过，不参与感知、不可见、不可选。尸体只作为障碍物参与可见弧计算，不作为“敌人”提供观测。

这一步只回答“本帧动作能不能选中某个新目标”，**不生成给策略的观测**。观测在 5.13 用最终状态生成。

“瞄准收窄”用上一帧结束时的锁定状态：

- 上一帧结束时有锁定 → 看其他敌人用 80° FOV；
- 上一帧结束时没有锁定 → 所有敌人用 90° FOV；
- 上一帧的锁定目标本身用 90° 算。

对**上一帧已经锁定的目标**，v1.2 也要求它在当前帧满足“存活、在 90° FOV 内、`p_vis > 0`”。只要离开 FOV、被完全遮挡或死亡，5.5 就立即把它视为不可选，5.6 视为“无”；不存在“先保留锁定、让 5.7 转回来”的例外。无敌不脱锁：目标进入无敌后仍可保持锁定并继续预瞄。这样策略不能隔着掩体或对着墙保持锁定，必须靠记忆和移动重新搜索。

## 5.6 第六步：目标选择与锁定

读取本帧动作里的目标选择：

- 如果选择“无”，本帧不锁定；
- 如果选择的是**上一帧同一个目标**：仍然必须同时满足“存活、当前可见（`p_vis > 0`）”。一旦它离开 FOV、被完全遮挡或死亡，本帧立即视为“无”；处于无敌仍保持锁定；
- 如果选择的是**新目标**：必须同时满足“存活、当前可见（`p_vis > 0`）”，否则视为“无”；
- 如果选择的敌人已死亡或当前不可见：视为“无”；处于无敌仍可选中并预瞄；
- 目标可以每帧切换，没有锁定延迟。

**v1.2 口径**：目标选择没有“保留上一帧锁定”的例外。mask 每帧重新计算，当前帧不可见的目标立即被 mask；锁定丢失后 `p_t = 0`，下一帧必须重新选择、重新收敛。

如果目标与上一帧不同，或上一帧没有锁定：

- `p_t = 0`；
- `tau_eff` 不在这里“锁定一次”，而是每帧按 8.8 用目标当前 `s_target` 连续计算。

如果目标与上一帧相同且一直锁着：

- `p_t` 保持连续；
- `tau_eff` 每帧随目标当前 `s_target` 连续变化，不是锁死值。

## 5.7 第七步：云台更新与转向后脱锁

- 有锁定：自动转向，按 4.5 节的 27°/帧上限；
- 没有锁定：手动转向。

自动转向的目标方向用 5.3 移动后的目标位置；转向后得到本帧最终云台角 `ψ_next`。

然后**用 `ψ_next` 和 5.3 移动后的位置**重新计算：

- 目标是否在 90° FOV 内；
- 目标可见弧 `p_vis` 是否 > 0；
- 目标是否存活。

如果转向后目标不再满足以下任一条件，锁定立即丢失：

- 目标存活；
- 目标在 90° FOV 内；
- 目标可见弧 > 0。

锁定丢失后：

- `p_t = 0`；
- 本帧不 fire；
- 下一帧按“无锁定”处理。

这一步仍然是“转向后脱锁”的判定点：目标可能因为移动太远、转 27° 后仍然追不进 90°，或者被掩体完全挡住。但由于 5.5 已经要求目标在当前帧可见，5.7 的脱锁主要处理“本帧转向过程中目标滑出 FOV”的情况；一旦脱锁，本帧不 fire，下一帧按“无锁定”处理。

## 5.8 第八步：更新命中率、开火、热量、伤害

第一步：对**所有存活机器人**做热量冷却和过热解除，不管它有没有锁定。

1. **先冷却**：普通 `heat = max(0, heat - 2)`；在己方启动区 `heat = max(0, heat - 4)`（冷却速度加倍）。
2. **检查过热解除**：如果 `overheated = true` 且 `heat <= 0`，把 `overheated` 设为 `false`。这一帧解除过热后，可以立刻开火。

第二步：对每个有锁定且通过 5.7 转向后检查的机器人：

3. 用 5.7 的最终云台角 `ψ_next`、5.3 的最终位置和 5.7 的最终 `p_vis` 计算本帧理想命中率 `p_ideal`（见第 8 节）。不要用 5.5 转向前的旧角度。
4. 用 `tau_eff` 更新 `p_t`。无敌状态不例外：锁定存在就照常收敛，允许预瞄。
5. 计算最终命中率 `p_final = p_t × m_spin`。
6. **检查开火条件**：必须同时满足第 7.4 节列出的全部 10 条。这里不再重复列一份短清单，避免两处条件不一致。
7. 如果满足，开火：
   - 本帧热量 +15（因为 15 发/s × 0.1 s × 10 热量/发）；
   - 热量夹到 160；
   - 如果热量 >= 160，设置 `overheated = true`；
   - 本帧对目标造成 `30 × p_final` 点期望伤害。
8. 如果不满足，不开火，不加伤害，不加射击热量。

注意：没有锁定的机器人也要冷却；否则一个过热后放弃锁定的机器人会永远停在 160，再也解不了过热。

开火结算后，再结算**对方启动区伤害**：所有站在敌方启动区、存活、非无敌的机器人，本帧 HP 减 8.125；这个伤害没有击杀者，可以打到 0 血，死亡在 5.9 统一处理，不给击杀分。

这一帧的所有伤害先记下来，最后统一结算，避免“谁先开火谁占便宜”。具体见第 10 节。

> 注意：热量顺序固定为“先冷却 → 再解除过热 → 再开火 → 再加热 → 再夹到 160 → 再设置过热”。不要写成“先开火再冷却”，否则热量降到 0 的那一帧能不能开火会分叉。

## 5.9 第九步：死亡与击杀

把所有本帧伤害同时结算：

- 目标血量减去本帧总伤害；
- 如果降到 0 或以下，目标死亡；
- 如果存在击杀者，击杀分 +10 给击杀者队伍；环境伤害/无击杀者死亡不加分；
- 死亡机器人变成尸体；
- 尸体保留死亡瞬间的速度，开始滑动。

同一帧多个射手打同一个目标：

- 伤害同时生效；
- 击杀者取“本帧对该目标打出的期望伤害最大”的射手，用的是扣血前的原始期望伤害，不是被目标剩余血量截断后的实际伤害；
- 如果原始期望伤害相同，取编号较小的射手；
- 队伍击杀分只加一次。

如果目标在本帧之前已经死亡，不能被选为目标，也不吃伤害。

目标死亡后，立即清空**所有以它为目标的锁定**：

- 把相关射手的 `target` 设为“无”；
- 把相关射手的 `p_t` 设为 0；
- 这不是等到下一帧 5.6 才做，而是在 5.9 死亡结算时就做。

因此下一帧 5.5 判断“上一帧结束时有没有锁定”时，用的是**已经清空后的状态**。否则目标刚死的那一帧，射手还带着旧锁定，下一帧其他敌人会错误地用 80° FOV 而不是 90° FOV。

本步结束后立即检查一次比分：

- 如果任一方 `score >= 90 - 1e-6`，比赛立即结束；
- 如果只有一方到 90，该方赢；
- 如果双方都到 90，平局；
- 如果结束，跳过 5.10、5.11、5.12，直接进入 5.13 生成终局观测/奖励；
- 如果没人到 90，继续 5.10。

这个检查必须在占点得分之前做。否则“击杀到 90”会被对手同一帧的 +0.1 占点分污染，甚至变成双方 90 的平局。

## 5.10 第十步：复活、无敌计时、回血

按第 11 节处理：

- 死亡计时；
- 复活；
- 无敌计时；
- 回血。

计时细节：

- 本帧刚死亡的机器人，本帧不扣复活计时；从下一帧开始扣。
- 本帧刚复活的机器人，本帧不扣无敌计时；从下一帧开始扣。
- 已经在死亡计时中的机器人，每帧减 0.1 s。
- 已经在无敌中的机器人，每帧减 0.1 s。
- 本帧无敌计时归零的机器人，本帧结束时解除无敌；它在本帧的占点统计中仍然算“无敌”，不计入人数。
- 本帧复活的机器人，本帧不参与占点，因为复活后立即进入无敌。

## 5.11 第十一步：占点得分

按第 13 节统计：

- 红方圈内人数；
- 蓝方圈内人数；
- 净占点人数 `net = 红方圈内人数 − 蓝方圈内人数`；红方每帧 `+0.1 × max(net,0)`，蓝方每帧 `+0.1 × max(-net,0)`。
- 训练 shaping：圈内每台存活、非无敌机器人每帧 `+0.001`（个人奖励）。

占点得分后，再检查一次比分：

- 如果任一方 `score >= 90 - 1e-6`，比赛立即结束；
- 如果只有一方到 90，该方赢；
- 如果双方都到 90，平局；
- 如果结束，跳过 5.12，直接进入 5.13。

## 5.12 第十二步：时间与结束

只有在 5.9 和 5.11 都没有结束时，才走这一步：

- 时间减 0.1 s；
- 检查时间是否到 0；
- 如果时间到 0，按 13.5 的 tiebreak 决定胜负；
- 如果时间没到 0，继续下一帧。

## 5.13 第十三步：观测与奖励

在 5.12 之后、帧末生成下一帧观测。此时必须使用**本帧最终状态**：

- 最终位置；
- 最终云台朝向 `ψ`；
- 最终存活/死亡/无敌状态；
- 最终血量；
- 最终热量、小陀螺、锁定目标、`p_t`；
- 最终比分、时间、占领人数、双方存活人数。

然后：

1. 用最终 `ψ` 和最终位置重新做 FOV 判断（锁定目标 90°，其他敌人按“最终是否有锁定”取 80°/90°）；
2. 重新计算可见弧 `p_vis`；
3. 只对最终可见的敌人采样血量噪声；
4. 生成 Action Mask；
5. 生成第 k+1 帧 5.1 读取的观测。

5.5 的几何结果只用于本帧 5.6 的选目标，不能拿来当观测；否则策略会看到云台转向、扣血、死亡、复活之前的过时状态。

奖励和日志也在这一步生成。然后进入下一帧。

# 6. 感知、视野与信息

## 6.1 FOV 的基本定义

每台机器人的 FOV 是 90°，也就是云台朝向左右各 45°。

所有视线、可见弧、开火判定都从**机器人圆心**出发，没有“枪口偏移”“相机偏移”“云台高度偏移”。这样 2D 几何是唯一的，不会出现“同一个目标，枪口能看见、圆心看不见”的分叉。

对目标 j，先算它相对自己的方位角：

```text
d = |p_j - p_i|
bearing = atan2(p_j.y - p_i.y, p_j.x - p_i.x)
```

距离退化约定：

- 如果 `d < 2r`（两圆重叠），所有几何量用 `d' = max(d, 2r)` 计算：最大可见弧、角速度、可见弧采样都用 `d'`。
- 如果 `d < 1e-6`（圆心重合），方位角不能用 `atan2(0,0)`：优先取上一帧两台机器人的相对方向；如果上一帧也重合，取 `+x` 方向。
- 命中率的距离因子 `p_dist` 仍用真实距离 `d`，但 `d < 0` 不可能；`d = 0` 时 `p_dist = 1`。
- 正常情况下，活机器人不会重叠：5.4 的碰撞会把它们分开。`d < 2r` 主要出现在“复活时尸体位置和别的机器人重叠”的那一帧，或者数值误差；`d = 0` 是极端退化，不是正常战斗状态。

再算它和云台朝向的夹角：

```text
err = wrap(bearing - ψ_i)
```

目标“在 FOV 内”的定义是：

```text
|err| <= 45°
```

注意：这个判断用的是**目标圆心**，不是目标圆的边缘。目标圆心在 45° 外，哪怕边缘擦进 FOV，也算不在 FOV 内。这样规则简单、可复现。

## 6.2 瞄准时的 FOV 收窄

当机器人上一帧结束时有锁定目标时，本帧进入“瞄准状态”。

瞄准状态下：

- 对**当前锁定目标**：仍然用 45° 半角；
- 对**其他敌人**：用 40° 半角，也就是总 FOV 80°。

为什么这样做：瞄准一个目标会收窄注意力，让机器人更难同时发现侧面的其他敌人；但已经锁定的目标不会因为收窄而立刻丢失。

**v1.2 口径**：如果锁定目标在本帧末离开 FOV/被完全遮挡，5.7 已经丢失锁定，下一帧不进入“瞄准收窄”，所有敌人恢复 90°；不允许用 80° 收窄 + 记忆去“盲锁”一个已经看不见的目标。

如果上一帧没有锁定，本帧所有敌人用 45° 半角。你可以在 44° 的位置发现一个新目标并锁定；锁定后它作为“锁定目标”继续用 45°，不会立刻丢。

## 6.3 最大可见弧

目标可见不等于“完全没有遮挡”。本文允许“只露一条边也能打”，所以需要计算可见弧。

设：

- 自己圆心 O；
- 目标圆心 C；
- 目标半径 `r = 0.30 m`；
- 距离 `d = |OC|`。

最大可见弧：

```text
full_arc = 2 × arccos(r / d)
```

这个公式的几何意义：从 O 向目标圆作两条切线，切点之间的正面弧。

几个值再强调一次：

| 距离 d | 最大可见弧 |
|---:|---:|
| 0.60 m（两圆贴住） | 120° |
| 1.00 m | 约 145° |
| 5.00 m | 约 173° |
| 12.00 m | 约 177° |

如果 `d < 2r`，说明两个圆重叠；按 6.1 的统一约定，用 `d' = max(d, 2r)` 代入 `full_arc`。这样两个圆重合时最大可见弧是 120°，不会出现 `arccos` 定义域错误。

## 6.4 实际可见弧

在正面弧上均匀取 64 个点。采样约定必须固定，不能由实现自己选：

```text
half_arc = full_arc / 2
φ_i = -half_arc + (i + 0.5) × (2 × half_arc) / 64,  i = 0..63
u = (O - C) / |O - C|          # 从目标圆心指向观察者；d≈0 时按 6.1 的兜底方向
P_i = C + r × rotate(u, φ_i)
```

也就是说，取的是 64 个**格子中心**，不是包含两个切点的端点；`i=0` 和 `i=63` 都不在切点上。

对每个点 P：

1. 从自己圆心 O 向 P 画一条线段；
2. 检查这条线段是否被以下东西挡住：
   - L 形掩体；
   - 短掩体；
   - 其他机器人（队友、敌人）；
   - 尸体；

   半径约定：采样点 `P_i` 取在**目标自身**的碰撞圆周上，`r = 0.30 m`；检查线段是否被其他机器人或尸体挡住时，其他机器人和尸体用**遮挡半径** `r_occ = 0.35 m`。不要把 0.30 和 0.35 混用。
3. 线段与遮挡形状采用**闭集相交**：擦边、相切都算挡住；
4. 采样点 P 自身不算遮挡；但线段穿过遮挡体内部、或 P 落在遮挡体内部，算挡住；
5. 如果没被挡住，这个点算可见。

统计可见点数 `n_visible`：

```text
p_vis = n_visible / 64
```

- `p_vis = 1`：完全可见；
- `p_vis = 0`：完全不可见；
- `0 < p_vis < 1`：部分可见，按比例乘命中率。

![可见弧示意：观察者、目标圆与中间遮挡物](docs/assets/rm_visibility_arc.svg)

图中 O 为观察者，右侧为目标圆；目标圆**面向观察者的一侧**才是采样弧。中间的机器人
（也可以是尸体或静态掩体）挡住了中间一段视线，所以绿色采样点可见、红色采样点被挡。
这张示意图的 `p_vis = 34/64`，即约 0.53，不是 0 或 1。观察/锁定使用 16 点粗采样；
开火与伤害使用完整的 64 点。注意图只画了一个圆形遮挡物；实际代码还会检查所有其他
机器人/尸体圆和 L 形/短掩体的边。

目标是否“可见”的判定：

```text
p_vis > 0
```

只要露一条边，就可以被锁定、被攻击；但命中率会按 `p_vis` 打折。

性能优化（不改变规则结果）：

- 选目标/维持锁定时，可以先用**中心射线**或低采样数做粗可见性判断；
- 只有真正进入开火判定、需要算本帧伤害时，才对该目标跑完整的 64 点 `p_vis`；
- 如果粗判说“可见”，但完整 `p_vis = 0`，本帧不开火；
- 锁定/选目标用粗判；开火与伤害用完整 `p_vis`；
- 如果锁定时粗判可见、开火时完整 `p_vis = 0`，本帧不开火，锁定按 5.7 在下一帧处理。

后续实现如果要用 `torchoptix`/硬件光线追踪，替换的是“线段与遮挡体求交”的实现，64 点采样和 `p_vis = n/64` 的规则不变。

这里有一个固定约定：**FOV 只用来判断“目标圆心是否在视场内”**。一旦圆心通过 FOV 判断，可见弧就只由掩体、机器人、尸体削减，不再按 FOV 边界裁剪。也就是说，目标圆心在 44.9° 时算在 FOV 内，哪怕它的一半圆已经出了 45° 边界，仍然按完整的正面弧去算遮挡。

## 6.4.1 当前几何观测接口（v1.21）

当前实现**不再使用 lidar**。actor 的 self token 末尾固定带 **8 个世界系墙/掩体距离**（蓝方按 180° canonical 旋转），用于替代“前方 128 点雷达”的导航信息：

```text
[self 24 维 | 8 向 clearance] = 32 维
```

- 8 向是固定的 45° 间隔方向，不是 128 条射线；
- 距离只到最近的静态墙/掩体，不含敌人/队友/尸体标签；
- 观测层不再有 lidar 的 180° 视场、128 点、16 m 量程这些接口；
- 锁定仍走 90° 相机 FOV + 可见性判定；8 向距离不授予锁定资格；
- 历史版本 v1.20 的 8 扇区 lidar encoder 已从当前 actor 中移除；旧 checkpoint 的 lidar 参数不再加载。

## 6.5 谁挡视线

以下都会挡：

- L 形掩体；
- 两条短掩体；
- 队友；
- 敌人；
- 尸体。

不挡的：

- 自己（不会挡自己的视线）；
- 目标自己（不会挡自己）；
- 墙（墙在场地边界，两个场内点之间的线段不会穿出场地）；
- 已经消失的弹丸（本文没有弹丸实体）。

尸体虽然不能选为目标，但它是实体，挡视线、挡移动。

## 6.6 探测距离

本文**不限制发现距离**。只要目标在 FOV 内、视线没被完全挡住，就能被发现，哪怕在场地另一头。

但是，命中率里的距离因子会在 12 m 降到 0：

```text
d >= 12 m → p_dist = 0
```

所以“看得见”不等于“打得到”。远距离发现主要用于：

- 知道敌人位置；
- 判断对方转点；
- 提前调整朝向；
- 给队友/策略提供信息。

## 6.7 可见敌人的信息

一个敌人可见时，机器人能知道：

- 位置（精确）；
- 速度（精确）；
- 云台朝向（带 ±5° 误差，见下）；
- 小陀螺程度（精确）；
- 血量（带噪声，见 6.8）；
- 是否存活（死亡状态是明确的，不靠血量猜）；
- 是否处于无敌（明确可见；它不影响选中/预瞄，只影响能否开火和是否会被伤害）；
- **是否开火**（本帧是否打出了一发，精确可见）。

云台朝向误差：

- 正常情况下，观察到的敌方云台朝向 = 真实朝向 + `U(-5°, +5°)`；
- 每个“观察者-目标”对、每帧独立采样；
- 如果目标在**被观察的这一帧开火**，观察者可以从弹道/枪口效果反推出准确朝向，这一帧的误差消除，直接给真实朝向；
- 开火后下一帧恢复 ±5° 噪声，除非它再次开火。

可选（默认关闭）：

- 目标开火后，观察者可以额外知道“它这一发锁的是谁”；
- 因为云台朝向已经能推出大概目标，这个信息不是必需；训练配置可以打开或关闭。

尸体（v1.5 起）：

- 尸体不能被选为目标；
- **可以被看到**：队友始终知道尸体的相对/绝对位置、朝向、复活倒计时；视野内敌人也能看到这些信息（敌人尸体需通过 FOV/可见弧）；
- 死亡单位的 mate/enemy token 保留这些 corpse 信息，`alive=0`；其余血量/热量/小陀螺/目标/开火等特征清零；
- 尸体仍作为可见弧/碰撞的几何障碍参与计算；
- 尸体没有血量、热量、目标、开火信息。

不能知道：

- 敌人的热量；
- 敌人是否过热；
- 敌人的命中率收敛值 `p_t`；
- 敌人当前锁定了谁（除非打开上面的可选项，或从云台朝向自行推断）；
- 敌人的未来动作。

## 6.8 血量观测噪声

可见敌人的血量不是精确值，而是：

```text
observed_hp = round(clamp(true_hp + N(0, σ_hp), 0, 325))
```

其中：

```text
σ_hp = 10 + 5 × s_target
```

- 目标不转小陀螺：`σ_hp = 10`，2σ = 20；
- 目标满小陀螺：`σ_hp = 15`，2σ = 30；
- 这里的 2σ 是“两倍标准差”；高斯分布下约 95% 的采样落在 ±2σ 内；所以不转时约 95% 的读数在真实血量 ±20 内，满转时约 95% 在 ±30 内；
- 中间连续变化；
- 每帧独立采样；
- 对每个“观察者-目标”对独立采样：A 看 B 的误差不影响 C 看 B 的误差；
- 只对可见敌人采样；不可见敌人没有血量观测；
- 结果夹在 0 到 325；
- 四舍五入到整数。

这对应你说的“2σ 落在 20 中”；不是 σ=20。小陀螺时 2σ=30，即 σ=15。

死亡状态不靠这个噪声判断：敌人死了就是死了，尸体不能被选为目标。

自己的血量、队友的血量是精确的，不加这个噪声。

## 6.9 受击方向提示

当机器人被击中时，它只知道“有个方向有人在打我”，不知道攻击者编号，也不知道精确位置。

规则：

1. 某一帧受到伤害时，在所有打中自己的攻击者里，取本帧**原始期望伤害最大**的那个。
2. 原始期望伤害是 `30 × p_final`，不是被剩余血量截断后的实际伤害。目标可能下一帧就死，溢出伤害没有意义，所以不需要按剩余血量截断。
3. 方向提示是所选攻击者相对自己的方位角，再加一个均匀分布的误差：

```text
cue = atan2(p_j - p_i) + U(-45°, +45°)
```

4. 提示只包含：
   - 一个世界坐标方向；
   - 没有攻击者编号；
   - 没有距离；
   - 没有血量；
   - 没有攻击者朝向；
   - 没有“是谁”的信息。
5. 提示只持续**命中当帧**；下一帧消失。它不自动刷新，除非再次被击中。
6. 提示可以穿掩体：你被打了，当然知道大概从哪边来。
7. 同一帧被多个攻击者打中：直接取本帧原始期望伤害最大的攻击者；如果伤害相同，内部任选一个，但对外仍然只给方向、不给编号。
8. 死亡/复活时清空提示。

这个提示的设计目的：被打了以后不能立刻获得敌人精确位置或身份，但至少知道该往哪边转；要获得精确位置，还是得把云台转过去、用 FOV 找到他。

## 6.10 队友信息共享

每台机器人始终知道存活队友的：

- 位置；
- 速度；
- 血量；
- 是否存活；
- 是否无敌；
- 云台朝向；
- 热量；
- 小陀螺程度；
- 当前锁定目标。

不共享：

- 队友看到的敌人位置；
- 队友的命中率收敛值 `p_t`；
- 队友的未来动作。

队友死亡后，共享 `alive = false`、尸体的相对/绝对位置、朝向、复活倒计时；死亡队友 token 保留这些 corpse 信息，其余特征清零（v1.5）。

敌人的位置、血量、热量、朝向不共享；只有“队友当前锁定目标”的编号共享。

也就是说：

- A 看到敌人，B 不一定知道位置；
- B 只能靠自己的 FOV 或受击提示；
- 不存在“全队小地图”；
- 队友目标编号只告诉你在打谁，不提供该敌人的位置/血量。

## 6.11 信息不对称总结

| 信息 | 自己 | 队友 | 可见敌人 | 不可见敌人 | Critic |
|---|---|---|---|---|---|
| 位置 | 精确 | 精确 | 精确 | 不知道 | 精确 |
| 速度 | 精确 | 精确 | 精确 | 不知道 | 精确 |
| 朝向 | 精确 | 精确 | ±5°（开火帧精确） | 不知道 | 精确 |
| 血量 | 精确 | 精确 | 带噪声 | 不知道 | 精确 |
| 是否无敌 | 精确 | 精确 | 精确 | 不知道 | 精确 |
| 热量 | 精确 | 精确 | 不知道 | 不知道 | 精确 |
| 小陀螺 | 精确 | 精确 | 精确 | 不知道 | 精确 |
| 目标 | 精确 | 精确 | 不知道 | 不知道 | 精确 |
| 是否开火 | 精确 | 精确 | 精确 | 不知道 | 精确 |
| `p_t` | 不知道 | 不知道 | 不知道 | 不知道 | 精确 |
| 未来动作 | 不知道 | 不知道 | 不知道 | 不知道 | 不知道 |

“不知道”在实现里就是不提供这一项，不是给 0 假装知道。策略可以用 recurrent memory 自己记，但规则不额外给。

# 7. 目标选择、云台与开火

## 7.1 目标选择

每帧策略从四个选项里选一个：

```text
0 = 不锁定
1 = 敌人 1
2 = 敌人 2
3 = 敌人 3
```

“敌人 1/2/3”是相对自己队伍的编号，和出生槽位绑定。

选择不是“按住 1.5 s”这种持续动作；它是每帧都可以改的离散选择。上一帧选 1，这一帧可以选 2，也可以选 0。

如果选择的敌人当前不可见，或者已经死亡：

- 本帧视为“不锁定”；
- 不报错；
- 不扣热量；
- 不造成伤害；
- 下一帧可以重新选。

**v1.2 口径**：这里的“当前不可见”包括“上一帧还锁着、这一帧刚离开 FOV”的目标。目标离开 FOV 的同一帧就立即 mask、立即丢失锁定，不允许继续对着墙或掩体保持锁定。策略要重新找到它，只能靠 GRU 记忆 + 移动/转云台。

## 7.2 锁定的含义

锁定同时意味着：

- 云台自动朝向它；
- 它是本帧唯一允许攻击的目标；
- 它的可见弧决定 `p_vis`；
- 它的距离、角速度、小陀螺决定命中率；
- 它死亡/离开 FOV/被完全遮挡时，锁定立即丢失。

锁定不意味着：

- 一定命中；
- 一定开火；
- 目标一定在 1° 内；
- 目标一定在 12 m 内。

## 7.3 云台自动朝向

有锁定时，云台每帧最多转 27°，按 4.5 节。

转向完成后，重新计算目标相对云台的角度。只有同时满足 §5.7 的三条：

```text
目标存活
目标在 90° FOV 内
p_vis > 0
```

锁定才继续存在。否则本帧不 fire，`p_t` 清零。

## 7.4 开火条件

本帧开火必须同时满足：

1. 自己存活；
2. 自己不是无敌；
3. 自己没有过热；
4. 自己的热量 < 160；
5. 有锁定；
6. 目标存活；
7. 目标不是无敌；
8. 目标可见（`p_vis > 0`）；
9. 目标距离 < 12 m（`p_dist > 0`）；
10. 云台角误差绝对值 < 1°；
11. 开火扳机 = 1（动作第 6 维）。

**瞄准与开火分离**：锁定、转云台、`p_t` 收敛都不消耗热量；只有扳机=1 且上面 11 条全部满足才开火。想停火只需扳机=0，可以继续锁定、预瞄、控热。

## 7.5 射速与“连续化”

射速是 15 发/s。本文不逐发模拟，而是把它连续化：

```text
每帧射击发数 = 15 × 0.1 = 1.5 发
每帧射击热量 = 1.5 × 10 = 15
每帧期望伤害 = 1.5 × 20 × p_final = 30 × p_final
```

这里的“1.5 发”不是真的打出半发弹丸，而是把 15 发/s 平均到 10 Hz 的帧上。伤害和热量都可以是小数。

如果目标剩余血量小于本帧期望伤害，只扣到 0，溢出伤害不计入 `total_damage`，但击杀仍然算。

## 7.6 角度误差

云台角误差：

```text
angle_error = wrap(bearing_to_target - ψ)
```

- `|angle_error| < 1°` 才能开火；
- 正好 1° 不能开火；
- 角度误差用目标圆心计算；
- 目标在移动，云台每帧最多转 27°，所以近距离横穿时可能跟不上，这是设计的一部分。

## 7.7 没有锁定时的行为

没有锁定时：

- 云台按手动转向；
- 不开火；
- `p_t = 0`；
- 不消耗射击热量；
- 仍然可以移动、占点、回血、被攻击。

# 8. 命中率

这一节是整份规则最核心的数值部分。先说直觉，再给公式。

## 8.1 直觉

一发抽象弹丸能不能打中，取决于：

1. **距离**：越远越难；
2. **自己动得快不快**：自己越晃越难；
3. **目标横向动得快不快**：目标横穿越难；
4. **目标露得多不多**：只露一条边就难；
5. **目标是不是在转小陀螺**：转起来更难打；
6. **自己是不是在转小陀螺**：自己转起来命中率上限下降；
7. **瞄了多久**：刚锁上时命中率从 0 慢慢收敛，不是瞬间满命中。

本文把这些因素乘起来，再乘小陀螺系数。

## 8.2 距离因子

采用“近距离平台 + 二次衰减”的弹道距离模型：

```text
if d <= 1.0:
    p_dist = 1.0
elif d < 12.0:
    p_dist = max(0, 1 - ((d - 1.0) / (12.0 - 1.0))²)
else:
    p_dist = 0.0
```

- `d <= 1 m`：1.0，近距离几乎必中；
- `d = 2 m`：约 0.992；
- `d = 5 m`：约 0.868；
- `d = 8 m`：约 0.595；
- `d = 10 m`：约 0.331；
- `d = 12 m`：0；
- `d > 12 m`：0。

这个函数在 1 m 处值和斜率都连续：1 m 内是平台，1 m 外按二次曲线衰减，12 m 归零。它比 `1-(d/12)²` 更符合“近距离弹道稳定、远距离迅速失准”的直觉，也不会在 1 m 内出现任何距离惩罚。

所以 12 m 是“能打到的极限”，不是“能看到的极限”。

## 8.3 自己移动因子

```text
p_self = 1 - 0.25 × min(1, |v_self| / 3)
```

- 自己静止：1；
- 自己 1.5 m/s：0.875；
- 自己 3 m/s：0.75；
- 自己超过 3 m/s 不可能，因为速度上限就是 3。

这里用的是自己的绝对速度，不是相对速度。自己动得越快，越难打。

## 8.4 目标角速度因子

先算目标相对自己的速度：

```text
v_rel = v_target - v_self
```

再算目标相对自己的角速度：

```text
ω = |cross(r, v_rel)| / d'²
```

其中：

- `r = p_target - p_self`；
- `cross(a, b) = a.x × b.y - a.y × b.x`，是二维叉积的标量；
- `d = |r|`；
- `d' = max(d, 2r)`，按 6.1 的退化约定；两圆重合时用 `d' = 2r`，不会除以 0。

这个公式只取“横向”成分。目标直直朝你冲过来，`cross` 接近 0，角速度小，命中率不会因为“它冲得快”而下降；目标横穿，`cross` 大，命中率下降。

角速度因子：

```text
p_motion = 1 / (1 + (ω / 0.75)²)
```

- `ω = 0`：1；
- `ω = 0.75`：0.5；
- `ω = 1.5`：0.2；
- `ω` 很大：接近 0。

这里把 1.5 rad/s 视为“最大角速度的一半”，此时命中率 0.2，符合你给的目标。

## 8.5 可见弧因子

```text
p_vis = n_visible / 64
```

- 完全可见：1；
- 一半可见：约 0.5；
- 只露一条边：很小，但仍可能 >0；
- 完全不可见：0，目标不可选。

`p_vis` 同时是“能不能看见”的开关和“露得多不多”的系数。

## 8.6 基础命中率

```text
p_base = p_dist × p_self × p_motion × p_vis
```

如果目标距离 ≥ 12 m，或者 `p_vis = 0`，则 `p_base = 0`，不能开火。

如果目标可见且距离 < 12 m，但 `p_base` 小于 0.02，则把它抬到 0.02。这是为了避免“理论上可见但命中率永远是 0”的数值死区；12 m 及以上仍然是 0。

## 8.7 自己小陀螺的命中率上限

```text
m_self = 1 - 0.1 × s_self
p_cap = 1.0 × m_self
```

- 这里的 `m_self` 是**乘数**，从 1 连续降到 0.9；
- 不转：`p_cap = 1.0`；
- 满转：`p_cap = 0.9`；
- 小陀螺需要 1.0 s 从 0 爬到 1，所以上限是在 1.0 s 内从 1.0 连续降到 0.9。

也就是说，理想条件下（1 m 内、双方静止、完全可见）不转小陀螺可以到 100% 命中；满转小陀螺最多 90%。`p_min = 0.02` 仍然是数值下限，不是物理规律。

然后：

```text
p_ideal = min(p_base, p_cap)
```

所以小陀螺不会让你的命中率变成 0，只是把上限压低。

## 8.8 命中率低通

`p_t` 从 0 开始，每帧向 `p_ideal` 靠近：

```text
alpha = 1 - exp(-dt / tau_eff)
p_t = p_t + alpha × (p_ideal - p_t)
```

- `dt = 0.1`；
- `tau_eff` 是当前帧的收敛时间常数，按目标当前 `s_target` 连续计算；
- 新锁定/切换目标/丢失目标：`p_t = 0`；
- 锁定但不开火：`p_t` 仍然继续收敛；
- 过热但仍有锁定：`p_t` 仍然继续收敛，等热量降到 0 可以立刻打；
- **无敌状态**：锁定存在时 `p_t` 照常收敛，允许预瞄；无敌结束后的第一帧可以直接以已经收敛的 `p_t` 开火。

`tau_eff` 不是锁定瞬间的阶跃，而是**随目标当前小陀螺程度连续变化**：

```text
tau_eff(t) = tau × (1 + 0.5 × s_target(t))
           = 0.4 × (1 + 0.5 × s_target(t))
```

- 目标不转：`tau_eff = 0.4 s`；
- 目标满转：`tau_eff = 0.6 s`；
- 中间连续变化；
- 如果锁定过程中目标开始小陀螺，`tau_eff` 随 `s_target` 增大而变长；
- 如果目标停止小陀螺，`tau_eff` 随 `s_target` 减小而变短；
- `p_t` 始终连续，不因为 `tau_eff` 变化而重置；
- 目标切换/丢失/死亡时，下一次锁定重新从 `p_t = 0` 开始，`tau_eff` 用新目标当时的 `s_target`。

自己的小陀螺**不改变** `tau_eff`。

无敌期间：

- 无敌机器人自己选中别人时，`p_t` 照常收敛，`tau_eff` 按目标当前 `s_target` 连续计算；这是允许的预瞄。
- 无敌机器人不能被别人选中，所以**别人打它**的锁定、`p_t`、`tau_eff` 都不存在，也不会增加。

## 8.9 目标小陀螺系数

```text
m_spin = 1 - 0.4 × s_target
```

最终命中率：

```text
p_final = p_t × m_spin
```

- 目标不转：×1；
- 目标满转：×0.6；
- 中间连续。

关键顺序：

1. 先算 `p_ideal`（包含自己的上限，不包含目标小陀螺）；
2. `p_t` 按 `tau_eff` 收敛到 `p_ideal`；
3. 最后乘 `m_spin`。

所以“已经瞄准”时，目标开始转小陀螺：

- `p_t` 不重置；
- `tau_eff` 不变；
- 最终命中率立刻乘 0.6；
- 之后 `p_t` 继续按原 `tau_eff` 收敛，最终值仍然是 `p_ideal × 0.6`。

## 8.10 伤害

```text
每帧期望伤害 = 30 × p_final
```

因为：

```text
1.5 发/帧 × 20 伤害/发 = 30
```

- 伤害是浮点数；
- 目标血量扣到 0 为止；
- 溢出伤害不计入 `total_damage`；
- 多射手同时打，按第 10 节结算；
- 没有友军伤害；
- 没有弹丸飞行时间；
- 没有弹丸下坠；
- 没有装甲方向。

## 8.11 一个数值例子

假设：

- 距离 5 m；
- 自己静止；
- 目标静止；
- 完全可见；
- 目标不转小陀螺；
- 自己不满小陀螺；
- 刚锁定。

则：

```text
p_dist   = 1 - ((5-1)/11)² = 0.868
p_self   = 1
p_motion = 1
p_vis    = 1
p_base   = 0.868
p_cap    = 1.0
p_ideal  = 0.868
```

`p_t` 从 0 开始，`tau=0.4`，每帧约完成 `1-exp(-0.25)=0.221` 的剩余差距。大约 1 s 后，`p_t` 接近 0.80；2 s 后接近 0.86。

如果目标在锁定后开始满小陀螺：

- `tau_eff` 随目标 `s_target` 增大而连续变长；
- `p_t` 不重置；
- 最终命中率乘 0.6；
- 所以同样的 `p_t`，实际伤害变成 0.6 倍。

# 9. 热量

## 9.1 热量是什么

热量是一个 0 到 160 的连续量。它表示“枪管/发射机构有多热”。热量越高，越接近过热；到 160 就不能开火。

热量不是弹药。本文没有弹药量，机器人可以无限打，只要热量允许。

## 9.2 参数

| 参数 | 值 |
|---|---:|
| 热量上限 | 160 |
| 每发弹丸热量 | 10 |
| 射速 | 15 发/s |
| 每帧射击热量 | 15 |
| 冷却速率（普通） | 20/s |
| 每帧冷却（普通） | 2 |
| 冷却速率（己方启动区） | 40/s |
| 每帧冷却（己方启动区） | 4 |
| 过热解锁 | 热量降到 0 |
| 官方 Q2 永久锁 | 不启用。Q2 是官方手册里“热量超过 Q0+100 后本局永久锁枪”的阈值；本规则没有这个机制 |

## 9.3 每帧热量变化

每帧按下面顺序：

1. 先冷却（己方启动区翻倍）：

```text
cool = 4 if 在己方启动区 else 2
heat = max(0, heat - cool)
```

2. 检查过热解除：

```text
if overheated and heat <= 0:
    overheated = false
```

3. 如果本帧开火：

```text
heat = heat + 15
```

4. 夹到上限：

```text
heat = min(heat, 160)
```

5. 如果 `heat >= 160`：

```text
overheated = true
```

关键：第 2 步在第 3 步之前。这样热量降到 0 的那一帧，先解除过热，然后可以开火；如果先开火再解除，就会少一帧。这个顺序与 5.8 和 16.40 完全一致。

## 9.4 过热后

过热后：

- 不能开火；
- 仍然可以移动；
- 仍然可以转云台；
- 仍然可以锁定目标；
- 仍然可以占点；
- 仍然可以回血；
- 仍然可以被攻击；
- `p_t` 仍然可以继续收敛（如果你还锁着）；
- 热量继续冷却：普通 2/帧，己方启动区 4/帧；
- 热量降到 0 时解锁。

从 160 降到 0 需要：

```text
160 / 20 = 8 s
```

## 9.5 连续射击的后果

这里必须按**离散帧**算，不能直接用连续时间 `160/13`。因为第 1 帧冷却会被 0 夹住，热量序列不是等差的。

从热量 0 开始，每帧都开火：

```text
第 1 帧：0 - 2 = 0（夹到 0），再 +15 = 15
第 2 帧：15 - 2 = 13，再 +15 = 28
第 3 帧：28 - 2 = 26，再 +15 = 41
...
第 12 帧：158
第 13 帧：158 - 2 = 156，再 +15 = 171，夹到 160，过热
```

所以：

- 前 12 个射击帧后热量是 158；
- 第 13 个射击帧才到 160 并过热；
- 也就是 **1.3 s**，不是 1.23 s。

从 0 到过热实际是 13 个射击帧。

### 9.5.1 已知的平衡后果

在“满血 325、伤害 20、射速 15/s”下，若从 0 热量开始一直锁定开火。下表中的 DPS 是“每秒期望伤害”的意思：

| 实际命中率 | 每帧伤害 | DPS | 击杀所需帧 | 结果 |
|---:|---:|---:|---:|---|
| 100% | 30.0 | 300 | 11 帧（1.1 s） | 击杀，热量 145，未过热 |
| 95% | 28.5 | 285 | 12 帧（1.2 s） | 击杀，热量 158，未过热 |
| 90% | 27.0 | 270 | 13 帧（1.3 s） | 击杀与过热同帧 |
| 85% | 25.5 | 255 | 13 帧（1.3 s） | 击杀与过热同帧 |
| 80% | 24.0 | 240 | 13 帧后目标剩 13 HP | 过热，冷却后补 1 帧，约 9.4 s |
| 70% | 21.0 | 210 | 13 帧后目标剩 52 HP | 过热，冷却后补 3 帧，约 9.6 s |

注意：

- 1 m 内、双方静止、完全可见、不转小陀螺时，可以到 100%；满小陀螺上限是 90%。
- 90% 和 85% 是“第 13 帧击杀，同时第 13 帧过热”；不是“过热前击杀”。
- 80% 和 70% 会在过热前打不死，然后进入约 8 s 的火力真空；实际 TTK 约 9.4–9.6 s。

这是“15 发/s + 160 上限 + 20 冷却 + 每发 10 热量”的必然结果，已按你的选择保留，不再自动降频或自动停火。

## 9.6 死亡与无敌

- 死亡瞬间热量清零；
- 无敌期间热量保持 0；
- 无敌期间不能开火，所以也不会增加热量；
- 复活后热量从 0 开始；3 s 无敌结束的同一帧进入过热门锁（heat=160、overheated=True），冷却到 0 后才能开火。

## 9.7 热量不参与命中率

热量不影响命中率，只影响“能不能开火”。热量高不会让弹道变散；只是到 160 直接锁枪。

# 10. 伤害、死亡与尸体

## 10.1 伤害来源

本文有两种伤害来源：

```text
17mm 抽象弹丸命中
对方启动区持续伤害（8.125 HP/帧）
```

没有：

- 碰撞伤害；
- 撞击伤害；
- 友军伤害；
- 自己的启动区伤害；
- 其他环境伤害。

碰撞只分两种：

- 低于阈值：推开，不扣血；
- 达到阈值：直接判负，不经过血量。

## 10.2 伤害结算

每帧：

1. 所有满足开火条件的机器人，按第 8 节算出 `p_final`；
2. 每台射手的本帧期望伤害是 `30 × p_final`；
3. 把同一目标受到的所有伤害加起来；
4. 目标血量减去总伤害；
5. 扣到 0 为止；
6. 溢出伤害不计入 `total_damage`；
7. 如果血量降到 0，目标死亡。

## 10.3 多射手与击杀分

同一帧多个射手打同一个目标：

- 伤害同时生效；
- 目标可能被多人“同时击杀”；
- 击杀者取本帧对该目标打出**原始期望伤害最大**的射手；
- 原始期望伤害相同，取编号较小的；
- 击杀分 +10 只加一次，给击杀者队伍；
- 其他射手没有击杀分，但他们的伤害计入 `total_damage`；
- 对方启动区伤害没有击杀者，不产生击杀分，也不计入 `total_damage`。

如果目标在本帧之前已经死亡：

- 不能被选为目标；
- 不吃伤害；
- 不产生击杀分。

## 10.4 死亡瞬间

机器人血量降到 0 时：

1. `alive = false`；
2. `hp = 0`；
3. 退出占领统计；
4. 热量清零；
5. 过热解除；
6. 小陀螺清零；
7. `p_t = 0`；
8. 锁定清空；
9. 保留死亡瞬间的位置和速度；
10. 变成尸体；
11. 开始 5.0 s 复活计时；
12. 如果击杀者存在，击杀者队伍 +10 分；对方启动区伤害等无击杀者死亡不加分。

死亡瞬间的速度就是尸体初始速度。尸体不会立刻停下。

死亡机器人的策略网络**不停止运行**：

- 它仍然接收观测；
- 它仍然用死亡瞬间的云台朝向（之后不再转动）做 FOV/可见性判断；
- 它仍然更新自己的循环记忆（GRU/LSTM 内部状态）；
- 它的动作输出被忽略，不能移动、不能转云台、不能开火、不能选目标；
- 它不能被别人选中；尸体的相对/绝对位置、朝向、复活倒计时可以被队友和视野内敌人看到（v1.5）；对应 mate/enemy token 保留这些信息、`alive=0`。

这样做的目的：让死亡期间的观察历史进入策略记忆，复活的瞬间模型已经“看过”这段时间的战场，而不是完全失忆。

## 10.5 尸体

尸体不是“另一个实体”，而是机器人自己的一个状态：

```text
ALIVE（活） → DEAD（尸体） → INVULNERABLE（无敌） → ALIVE（活）
```

整个过程中机器人编号不变、碰撞圆不变、遮挡圆不变、队伍不变；不删除实体，也不新建一个“复活机器人”。所谓“复活”，是同一个实体从 `DEAD` 切到 `INVULNERABLE`，位置不变，再从 `INVULNERABLE` 切回 `ALIVE`。

`DEAD` 状态：

- 半径 0.30 m；
- 质量 1（归一化）；
- 碰撞形状和活机器人一样；
- 保留死亡瞬间的位置和速度；
- 会继续滑动；
- 始终按最大减速度 5.0 m/s² 减速；
- 会和活机器人、其他尸体做等质量非弹性碰撞；
- 会被推动，也会推别人；
- 会挡移动；
- 会挡视线；
- 不能被选为目标；
- 没有血量；
- 不能开火；
- 不占点；
- 不产生击杀分；
- 不触发受击提示。

尸体减速：

```text
每帧移动步（5.3）开始时，速度大小减少 5.0 × dt = 0.5 m/s
```

也就是从 3 m/s 到停下大约 0.6 s。如果速度小于 0.01 m/s，直接置 0，避免无限微小滑动。

“始终按最大减速度”指：

- 它没有自己的推进力；
- 每帧都扣 0.5 m/s；
- 碰撞可以在这一帧改变它的速度，但下一帧仍然扣 0.5 m/s；
- 不会因为被撞而“越滑越快”且不衰减；
- 尸体没有自己的推进力；等质量非弹性碰撞只是在参与者的速度之间取平均，不会凭空超过场上最大速度 3 m/s；之后按 5.0 m/s² 减速。

尸体撞墙/掩体：

- 位置修正；
- 法向速度清零；
- 不判负；
- 不扣血。

尸体和活机器人碰撞：

- **做等质量非弹性碰撞（法向速度取均值）**，和活机器人撞活机器人一样；
- 双方速度都可能改变；
- 尸体可以被推得很快，也可以把活机器人推走；
- 但尸体没有“主动方”资格：判负只判活机器人自己的法向分量；
- 如果活机器人朝尸体的法向速度 >= 2.0 m/s，判活机器人主动方全队负；
- 如果 < 2.0 m/s，不判负，只做等质量非弹性分离/速度修正；
- 尸体所属队伍不会因为**敌方**撞自己的尸体而输；
- 但如果撞尸体的是**同队队友**，按 12.5 的队友碰撞判该队负；队友尸体不豁免；
- 尸体被撞后仍然每帧减速 5.0 m/s²。

尸体和尸体碰撞：

- 等质量非弹性碰撞（法向速度取均值）；
- 不判负；
- 两者都继续每帧减速。

如果尸体把活机器人推着撞墙/掩体：

- 墙/掩体判负仍然按活机器人自己的法向速度判；
- 不因为“是尸体推的”而豁免；
- 尸体所属队伍不会因为**敌方**撞自己的尸体而输；同队队友撞尸体仍按 12.5 判该队负；活机器人可能因为撞墙而输。

## 10.6 尸体与视线

尸体挡视线，和活机器人一样，使用 0.35 m 遮挡半径。

但尸体不能被选为目标，也不提供血量/热量信息。它只是一个障碍物。

## 10.7 尸体与占点

尸体不占点。死亡瞬间就退出占领统计。

## 10.8 尸体与复活位置

复活位置是“复活结算时尸体所在的位置”，不是死亡瞬间的位置，也不是“未来最终停止的位置”。

这里没有“删除尸体、再新建一个机器人”的过程；尸体是同一个机器人的 `DEAD` 状态，复活是同一个实体切换状态，位置不变。

如果尸体在 5.0 s 内被推动，复活位置跟着变；如果 5.0 s 到点时尸体还在滑，就以那一刻的位置为准。

即使这个位置在掩体里、墙外、或和别的机器人重叠，也**原地复活、不位移**；下一帧按物理规则分离；复活速度为 0，不满足判负速度阈值，所以不判负、不扣血。

# 11. 复活、无敌与回血

## 11.1 复活计时

死亡后：

```text
复活计时 = 5.0 s
```

每帧减 0.1 s。到 0 时复活。

死亡那一帧不扣计时；从下一帧开始扣。这样从死亡到复活是完整的 5.0 s，而不是 4.9 s。

不是官方那种“首次 5 s、之后每次 +5 s 读条”；本文固定 5.0 s。

## 11.2 复活位置

复活位置 = **复活结算时尸体所在的位置**（本帧移动和碰撞之后、状态切换之前的位置）。

不是“未来最终停止的位置”：如果 5.0 s 到点时尸体还在滑，就以复活结算那一帧的位置为准；状态切换后，同一实体不再以 DEAD 状态继续滑。

本文**不限制**复活必须在己方半场：

- 尸体滑到对方半场，就在对方半场复活；
- 尸体滑到中央圆，就在中央圆复活；
- 复活后 3 s 无敌，但无敌期间不占点、不能开火；
- 这是“尸体可能被推走”的自然结果，也是本文保留的战术风险。

复活时**不搜索、不位移、不换点，也不删除/重建实体**：

- 机器人编号、碰撞圆、遮挡圆、队伍都不变；
- 同一个实体从 `DEAD` 直接切到 `INVULNERABLE`；
- 位置保持 `C0` 不变；
- 即使 `C0` 和墙、掩体、别的机器人、别的尸体重叠，也**不在复活瞬间移动**；
- 复活当帧不结算碰撞；从下一帧开始按物理规则分离；
- 如果 `C0` 在墙/掩体里，下一帧做位置修正；复活速度为 0，不满足判负速度阈值，所以不判负、不扣血；
- 如果 `C0` 和别的机器人重叠，下一帧做无伤害的位置分离；
- 如果 `C0` 在对方机器人正上方，就在对方机器人正上方复活；这就是“尸体被推到哪里，就在哪里复活”。

注意：无敌机器人和别的机器人是物理实体，会互相推挤；所以“复活瞬间不位移”只保证复活那一帧，下一帧的正常碰撞仍然会把它推开。这个推开不是“复活传送”，是物理分离。

复活瞬间不判负、不扣血；下一帧的正常碰撞仍然按判负规则处理。

复活时：

- `hp = 65`；
- `heat = 0`；
- `overheated = false`；
- `spin = 0`；
- `p_t = 0`；
- 目标清空；
- 受击提示清空；
- 速度 = 0；
- 云台朝向 = **继承死亡帧的云台朝向**（死亡期间云台不更新，`yaw` 冻结；复活时直接沿用该值）；不随机、不强制面向场地中心/敌人；
- 进入 3 s 无敌；
- 无敌计时 = 3.0 s；
- 复活当帧不结算回血，从下一帧开始回血。

## 11.3 无敌

无敌持续 3 s。

复活那一帧不扣无敌计时；从下一帧开始扣。这样从复活到无敌结束是完整的 3.0 s。

无敌期间：

- 可以移动；
- 可以转云台；
- 可以锁定目标；
- **锁定可以存在，`p_t` 照常收敛，允许预瞄**；无敌结束后的第一帧可以直接以已经收敛的 `p_t` 开火；无敌期间 `tau_eff` 也按目标当前 `s_target` 连续计算；这里说的是“无敌者自己锁定别人”；别人也可以选中/锁定/预瞄它，但弹丸不会造成伤害，`p_final` 仍可计算；
- 不能开火；
- 不受弹丸伤害（碰撞判负仍然生效，见 11.5）；
- 不占点；
- 不产生击杀分；
- 挡视线；
- 可以回血；
- 热量保持 0；
- 小陀螺可以转，但不改变“不能开火”；
- **可以被敌人选中/锁定/预瞄**；但无敌期间弹丸伤害为 0，敌人可以提前站位、等无敌结束的瞬间再开火；
- **无敌状态算存活**：队友信息共享、回血、终局总血量都按存活算；但它不占点、不产生击杀分；
- **仍然是物理实体**：与机器人、尸体、墙、L 形掩体、短掩体都碰撞；会挡移动、会被推、也会推别人；
- 它可以用身体堵路、把别人挤出中央圆；但无敌结束后就恢复正常，停在危险位置会被马上击杀；
- **无敌不免疫碰撞判负**：判负逻辑高于无敌逻辑。它高速撞人、撞墙、撞掩体，照样按主动方判负；别人高速撞它，也照样判别人负；
- 无敌只是“免疫弹丸伤害、不能被选为目标、不占点”，不是“免死金牌”；
- 无敌结束后如果和别的机器人重叠，只做无伤害的位置分离；分离过程不产生速度，不判负。

无敌期间回血：

- 在己方启动区里，按 81.25/s 回血；
- 可以从 65 回到 325；
- 5 s 最多回 406.25，足够回满；
- 所以如果复活在启动区，3 s 无敌结束时可能已经满血。

这是“防止虐泉”的设计：复活的人有 3 s 无敌，并且可以在泉水里回满，对手不能一直堵在出生点杀。

## 11.4 无敌结束

无敌计时到 0 时：

- `invulnerable = false`；
- **本帧 `heat = heat_max`、`overheated = True`**；必须先从过热冷却到 0，才能再次开火（v1.21；不是复活瞬间热锁）；
- 可以转向、锁定、移动；
- 血量保持当前值，不强制回到 65；
- 如果之前在泉水里回满，就是满血；
- 如果没回，最少是 65；回了血就更高，最高 325。

## 11.5 无敌与碰撞

无敌机器人是**实打实的物理实体**：

- 会挡移动；
- 会挡视线；
- 会被别人推；
- 也会推别人；
- 会撞墙、撞 L 形掩体、撞短掩体、撞尸体；
- 参与位置分离和速度修正。

**判负逻辑高于无敌逻辑。** 无敌只提供：

- 不受弹丸伤害；
- 不能被敌人选为目标；
- 不占点；
- 不产生击杀分；
- 可以回血。

无敌**不提供**：

- 碰撞免责；
- 撞墙免责；
- 撞人免责；
- 被撞免责。

所以：

- 无敌机器人高速撞别人：按主动方判负，照样输；
- 别人高速撞无敌机器人：按主动方判负，别人照样输；
- 无敌机器人高速撞墙/掩体：照样输；
- 无敌机器人被推着撞墙/掩体：照样按它的法向速度判；
- 双方同责：双方判负，本局平局。

物理推动仍然存在。它可以把别人顶开、堵路、挤出中央圆，但如果动作太大，自己就会因为碰撞判负。这是“无敌可以回家，但不能用无敌换命”的实现。

无敌结束后，如果它和别的机器人仍然重叠，只做一次无伤害的位置分离；分离过程不产生速度，不判负、不扣血。

## 11.6 回血

回血区域是己方 2.5 m × 2.5 m 启动区。

回血速度：

```text
81.25 HP/s
```

每帧：

```text
hp = min(325, hp + 8.125)
```

回血条件：

- 存活；
- 圆心在己方启动区内；边界算区内；
- 死亡不回；
- 无敌可以回（见 11.3）。

回血不要求：

- 静止；
- 不要求不开火；
- 不要求不受击；
- 不要求面向某个方向。

受击不会中断回血。也就是说，一个机器人在泉水里一边被打一边回血，回血仍然生效。

对方启动区是伤害区：

- 每帧扣 8.125 HP，和回血速率相同；
- 可以把人打到 0 血；
- 死亡没有击杀者，不给击杀分；
- 无敌机器人不受这个伤害；无敌结束若还在对方启动区，开始扣；
- 伤害区不产生受击方向提示（不是敌方弹丸）。

## 11.7 回血与热量

回血不影响热量。回血不能降温，冷却只按第 9 节。

# 12. 碰撞与判负

## 12.1 总原则

本文的碰撞规则是“硬规则”：

- 低于阈值：只推开，不扣血；
- 达到阈值：主动方全队立即输掉本局。

没有“碰撞伤害”“碰撞扣分”“碰撞眩晕”这些中间状态。

**v1.2 口径**：所有 6 台机器人两两参与碰撞，不按队伍过滤；队友、尸体、无敌单位都是物理实体。队友高速相撞同样判该队负；尸体没有主动方资格，但活人撞尸体仍按活人的法向速度判；无敌不豁免碰撞判负。

## 12.2 墙和掩体的法向速度

对墙/掩体：

- 法向 `n` 是接触面朝机器人外侧的方向；
- 机器人速度 `v`；
- 法向速度：

```text
v_n = dot(v, n)
```

- 只有朝墙里运动时 `v_n` 为负；
- 撞击速度取：

```text
impact = max(0, -v_n)
```

- 如果 `impact >= 2.5 m/s`，判该机器人所在队伍负。

注意：

- 擦墙不算，因为切向速度不算；
- 贴着墙慢慢推不算，因为法向速度很小；
- 被别的机器人推着撞墙，仍然按被推者的法向速度算，不豁免；
- 推人者如果机器人碰撞也达到 2.0 m/s，会同时判负；如果没达到，只有被推者撞墙判负。

## 12.3 机器人之间的相对法向速度

两个机器人 i 和 j：

```text
n = (p_j - p_i) / |p_j - p_i|
```

`n` 从 i 指向 j。

相对速度：

```text
v_rel = v_i - v_j
```

相对法向速度：

```text
impact = max(0, dot(v_rel, n))
```

- 两车相向而行，`impact` 大；
- 同向同速，`impact = 0`；
- 一辆车追另一辆，`impact` 是接近速度；
- 两车擦身，`impact` 小。

如果 `impact >= 2.0 m/s`，进入判责。

## 12.4 主动方

每台机器人朝对方的法向分量：

```text
c_i = max(0, dot(v_i, n))
c_j = max(0, dot(-v_j, n))
```

- `c_i` 是 i 朝 j 冲的分量；
- `c_j` 是 j 朝 i 冲的分量。

判责：

- 如果 `|c_i - c_j| <= 0.1 m/s`：双方同责；
- 否则，`c` 更大的那一方是主动方。

同责时：

- 如果 i 和 j 是不同队伍：双方都判负，本局平局；
- 如果 i 和 j 是同一队伍：该队判负（自己人撞自己人，没有“双方平局”）。

主动方明确时：

- 主动方所在队伍立即输；
- 被动方赢。

## 12.5 队友碰撞

队友高速相撞也判负：

- 阈值同样是相对法向速度 2.0 m/s；
- 主动方队伍输；
- 同责时该队输；
- 不存在“队友豁免”。

这是安全规则：不管撞谁，高速撞就是危险行为。

## 12.6 尸体碰撞

尸体仍然是机器人实体，碰撞用和活机器人一样的等质量非弹性碰撞：

- 位置各承担一半；
- 法向速度各承担一半；
- 切向保留；
- 不做反弹。

物理上它和活机器人没有区别；区别只在“判负资格”：

- 尸体没有主动方资格；
- 活机器人撞尸体时，只判活机器人自己的法向分量；
- 活机器人朝尸体的法向速度 >= 2.0 m/s：活机器人主动方全队负；
- 活机器人朝尸体的法向速度 < 2.0 m/s：不判负，只做等质量非弹性分离/速度修正；
- 尸体朝活机器人滑过来：尸体不判负，活机器人也不因为“尸体撞我”而输；两者只做等质量非弹性碰撞；
- 尸体所属队伍不会因为**敌方**撞自己的尸体而输；
- 但如果撞尸体的是**同队队友**，按 12.5 的队友碰撞判该队负；队友尸体不豁免；
- 尸体撞墙/掩体：位置修正、法向速度清零、不判负、不扣血。

尸体碰撞后仍然每帧减速 5.0 m/s²。

## 12.7 无敌碰撞

无敌机器人是物理实体，碰撞照常做位置分离和速度修正；**判负判定也照常做**：

1. **无敌机器人 vs 活机器人**：正常分离、正常速度修正；按 12.3/12.4 判主动方，该谁输谁输；不扣血、不产生击杀分。
2. **无敌机器人 vs 尸体**：正常分离、正常速度修正；按 12.6 处理，尸体没有主动方资格，只判无敌机器人自己的法向分量；不扣血、不产生击杀分。
3. **无敌机器人 vs 墙/L 形掩体/短掩体**：正常位置修正、法向速度清零；按 12.2 判负。
4. **无敌机器人被推**：按它自己的法向速度判，不因为它“无敌”就豁免。

没有“0.2 s 豁免”，也没有“涉及无敌就不判负”。判负逻辑高于无敌逻辑。

无敌只影响“弹丸伤害、被选为目标、占点、击杀分、回血”，不影响碰撞判负。

## 12.8 低于阈值的碰撞

低于阈值时：

- 把重叠的机器人分开；
- 把法向相对速度清零；
- 切向速度保留；
- 不扣血；
- 不判负；
- 不产生击杀分；
- 不产生受击提示。

具体修正：

设单位法向 `n` 从 i 指向 j，闭合速度：

```text
v_imp = (v_i - v_j) · n
```

如果 `v_imp > 0`，两台等质量机器人做完全非弹性碰撞：

```text
v_i' = v_i - 0.5 × v_imp × n
v_j' = v_j + 0.5 × v_imp × n
```

碰撞后两者法向速度相等（都等于法向质心速度），切向速度不变。恢复系数 `restitution = 0`；不做反弹。

- 两台机器人（无论活/死）都 movable、质量都为 1：重叠量各承担一半；法向速度按上式各承担一半。
- 墙不可动：机器人承担全部重叠修正；机器人朝墙的法向速度清零，切向保留。
- 尸体和活机器人质量都为 1：同样按上式各承担一半；尸体碰撞后仍然每帧减速 5.0 m/s²。
- 这就是“等质量非弹性碰撞”，不是“速度交换”；速度交换是 `e=1` 的完全弹性碰撞，本规则不使用。

分开的位置修正不产生额外伤害。

## 12.9 判负的结算

一旦判负：

- 本局立即结束；
- 本帧不再进行感知、锁定、开火、占点、计时；
- 比分冻结；
- 判负方输，另一方赢；
- 如果双方同责：平局；
- 如果同一帧有多起判负，只要涉及两个队伍，就是平局；只涉及一个队伍，该队输。

判负不产生击杀分，也不看当前比分。

## 12.10 判负与时间

- 判负发生在时间到之前：判负优先；
- 判负和最后一帧同时发生：判负优先；
- 判负后不再结算占点分，也不再加时。

## 12.11 碰撞检测的几何

墙：

- 机器人圆心越过 `x = ±5.70` 或 `y = ±3.70`；
- 推到边界，法向速度清零。

L 形掩体：

- 机器人圆和 L 形多边形相交；
- 按 12.11.1 的“实心区域最近点”推出，不把内部接缝当外墙；
- 法向速度清零；
- 如果法向撞击速度 >= 2.5，判负。

短掩体：

- 机器人圆和 0.15 × 1.80 矩形相交；
- 同上。

机器人：

- 两个圆相交；
- 沿圆心连线分开；
- 法向相对速度清零；
- 如果相对法向速度 >= 2.0，判责。

尸体：

- 同机器人圆碰撞；
- 但判责只针对活机器人；
- 尸体不判负。

### 12.11.1 并列/退化情况的固定处理

为了避免“实现不同、结果不同”，下面这些退化情况必须按固定方式处理：

1. **两个机器人恰好同心**：不能用圆心连线定法向。优先使用上一帧两台机器人的相对方向；如果上一帧也同心，使用 `+x` 方向。
2. **机器人同时撞墙的两个面（角落）**：分别计算 x 方向和 y 方向的法向撞击速度，取较大的那个作为判负依据；不把两个方向相加。
3. **任意多边形掩体（L 形 6 边形、短掩体矩形）**：不能把 L 拆成两个独立矩形，也不能沿“最近边”硬推。统一用“实心区域最近点”：
   - 求掩体实心区域（闭集）上离机器人圆心 `C` 最近的点 `Q`；
   - `d = |C - Q|`；
   - 如果 `d < 0.30` 且 `d > 1e-6`：单位外法向 `n = (C - Q) / d`，把圆心推到 `Q + 0.30 × n`；在边上时 `n` 自然垂直于边，在凸顶点时 `n` 自然从顶点指向圆心，不会横向瞬移；
   - 如果 `d <= 1e-6`（圆心已深入掩体内部）：退化为向最近的外表面边推出，忽略 L 形两个矩形重叠处的内部接缝；
   - 判负用推出前的法向速度：`impact = max(0, -v · n)`；撞墙阈值用 2.5 m/s。
4. **同一帧多起碰撞的全局顺序**：每轮按下面固定顺序处理，不能按集合遍历的随机顺序：
   - 先墙：x 轴两面，再 y 轴两面；
   - 再掩体：红 L 多边形、蓝 L 多边形、红短掩体、蓝短掩体；
   - 再机器人对：按全局编号 `(i, j)` 升序，`i < j`，遍历所有 15 对；尸体也按它的全局编号参加，不单独排到最后。
5. **立即应用**：每一对检查完就立即应用位置分离和速度修正，再处理下一对；不是全部检查完再统一应用。这样同一帧的结果与顺序绑定，但顺序是固定的。
6. **判负用速度快照**：所有 2.0 / 2.5 m/s 的判负检查，统一使用 5.3 结束时的速度快照，不使用位置修正后的速度。位置修正只影响后续对的几何，不影响本帧已经做的判负判定。
7. **判负即停**：任何一对达到判负阈值，立即停止后续对，进入 12.9；不要再做剩余的位置分离。
8. **两轮迭代**：
   - 第 1 轮做完整处理：判负检查（用 5.3 速度快照）+ 位置分离 + 速度修正；
   - 第 2 轮只做纯位置分离，解决残余重叠；**不再检查判负，也不再修改速度**；
   - 第 2 轮后仍然重叠就保留微小重叠，下一帧继续分离。
9. **速度修正**：低于阈值的碰撞，只清零法向相对速度，保留切向速度；不反弹，不增加速度。
10. **尸体速度很小时**：小于 0.01 m/s 直接置 0，不再做无意义的滑动。

## 12.12 连续推挤终局（v1.21）

除了第 12.1–12.3 节的一次性高速碰撞判负，当前实现还检测**持续推挤**：

**推墙/掩体**：

- 存活机器人用 `v_pre`（指令速度）朝墙/掩体法向推；
- 法向分量 > `0.05 m/s` 且连续 **1.0 s** → 终局；
- 只罚主动推的机器人；队友 -0.5，对手 0。

**推人/尸体**：

- 只给活着的主动推人者计时；队友、对手、尸体都算；
- 法向相对速度 > `0.3 m/s`，连续 **0.5 s** → 终局；
- 被推者不累计计时；
- 单方推：主动方 -10，队友 -0.5，对手 0；
- 双方都在推：平局，双方主动方 -10，双方非主动队友 -0.5；
- 对应的终局码：24/25/26（推墙/掩体：红胜/蓝胜/双方），27/28/29（推人：红胜/蓝胜/双方）。

终局罚分是**每台机器人**；dense 的贴人/冲击/推挤惩罚仍然保留。当前训练可以用 `--no-body-push-terminal` 只关闭推人终局做消融，但默认比赛规则是开启。


# 13. 占点、比分与胜负

## 13.1 占领人数

每帧统计：

```text
red_occ = 红方存活、非无敌、圆心在中央圆内的机器人数
blue_occ = 蓝方存活、非无敌、圆心在中央圆内的机器人数
```

- 死亡不计；
- 尸体不计；
- 无敌不计；
- 圆心距离 <= 1.5 m 算圈内；
- 正好在边界上算圈内。

## 13.2 占领得分

```text
net = red_occ - blue_occ
if net > 0:
    红方 +0.1 × net 分
elif net < 0:
    蓝方 +0.1 × (-net) 分
else:
    不加分
```

也就是每秒 +1 分，但按 10 Hz 拆成每帧 +0.1。

关键：

- 按净人数，不是简单多数；
- 3v0：红方 +0.3/帧（3 分/s）；2v0：+0.2/帧；2v1：+0.1/帧；
- 1v1、2v2、0v0 净人数为 0，不加分；
- 圈内人数按存活、非无敌机器人统计。

## 13.3 击杀分

每次击杀：

```text
击杀者队伍 +10 分
```

- 只加一次；
- 被多人同时打，按 10.3 节选击杀者；
- 碰撞致死不存在（碰撞是判负，不是扣血）；
- 尸体不产生击杀分；
- 自杀不存在（没有环境伤害）。

## 13.4 比分

比分是浮点数：

```text
score = 占领分 + 击杀分
```

没有“扣分”。判负直接结束比赛，不走比分。

显示时保留 1 位小数。

## 13.5 胜利条件

按优先级：

1. **先到 90 分**：本局立即结束，先到者赢；
2. **时间到 180 s**：比分高者赢；
3. **比分相同**：比较全队累计造成伤害，伤害高者赢；
4. **伤害相同**：比较终局全队存活机器人总血量，血量高者赢；
5. **仍然相同**：平局。

这里的“tiebreak”就是“比分相同后继续比较的规则”，顺序是：先比总伤害，再比总血量，最后才平局。

注意：

- 先到 90 是“立即结束”，不是打满 180 s；
- **训练课程例外（v1.7）**：允许把 `target_score` 临时调低（30 s → 20，120 s → 80）让短片也能结束；最终评测为 180 s/90；
- 90 的检查发生两次：一次在击杀结算后（5.9），一次在占点结算后（5.11）；先发生的那次优先；
- 分数比较用 `score >= 90 - 1e-6`，避免浮点误差导致 89.999999 不算到；
- 如果同一帧既有人到 90、时间也到 0，先判 90；90 优先于时间；
- 同一帧双方都到 90：判平局，双方每台机器人都拿“双方到 90”的终端奖励 +2；
- 时间到时双方都不到 90，按比分；
- 时间到时比分相同，按伤害；
- 伤害相同，按总血量；
- 总血量只算存活机器人，死亡算 0；
- 无敌机器人算存活，血量算入总血量。

## 13.6 双方同时到 90

同一帧双方都达到 90：

- 比赛判平局；
- 不给任何一方“先到”胜利；
- 训练时双方每台机器人终端奖励 +2；
- 这不是“突然死亡”，也不是“比分高者胜”。

## 13.7 双方同时犯规

同一帧双方都严重犯规：

- 比赛判平局；
- 双方都算输；
- 训练时每个步兵终端奖励 -10；
- 不比较比分。

## 13.8 总伤害

`total_damage` 是：

- 本队对敌方机器人造成的实际扣血量；
- 不含溢出伤害；
- 不含碰撞；
- 不含对自己/队友的伤害（没有友军伤害）；
- 不含对方启动区伤害（没有击杀者）；
- 用于时间到平局时的 tiebreak。

## 13.9 总血量

终局总血量：

- 每台存活机器人当前血量之和；
- 死亡机器人算 0；
- 无敌机器人算存活；
- 尸体不算；
- 用于 tiebreak。

## 13.10 比分与时间的关系

- 先到 90：立即结束；
- 时间到：按 13.5；
- 判负：立即结束，优先于比分和时间；
- 平局：双方都到 90、双方犯规、或 tiebreak 仍相同。

## 13.11 空局终止（v1.21）

如果连续 **10.0 s** 没有开火/伤害、实际回血、中心占点等事件，比赛以 `OUTCOME_STAGNATION=23` 结束，双方 `winner=0`。

空局终局不是普通平局：每台机器人最多扣 `stagnation_penalty=5.0`，并按以下三项折扣（各自最多减半后连乘）：

- 最近障碍 clearance；
- 离自己出生点的距离（越远扣得越少）；
- 队伍存活质心离中心更近的一队（近队最多少扣 50%）；
- 另加移动速度 EMA 折扣（总时长内移动越多，扣得越少，最多减半）。

这是训练/比赛共用的终止规则，用来避免双方在掩体后无限对峙。


# 14. 通信与 Critic

## 14.1 通信

每台机器人独立决策。队伍内共享：

- 队友位置；
- 队友速度；
- 队友血量；
- 队友是否存活；
- 队友是否无敌；
- 队友云台朝向；
- 队友热量；
- 队友小陀螺程度；
- 队友当前锁定目标。

不共享：

- 队友看到的敌人；
- 队友的 `p_t`；
- 队友的未来动作；
- 敌人的位置、血量、热量、朝向（队友目标编号除外）。

敌人信息只能靠自己的 FOV、可见弧、受击提示。

例外：**比分、时间、占领人数、双方存活人数**是裁判系统/HUD 公开信息，不属于“敌人位置/血量”情报，可以进入 Actor 观测。它们只给聚合数字，不给敌人位置、朝向、血量、热量、目标。

## 14.2 Critic

先明确两个词：

- **Actor（策略网络）**：部署时真正根据观测输出动作的网络；它只能看“机器人自己能看到的信息”。
- **Critic（价值网络）**：只在训练时使用，用来估计全局状态的价值；它可以看全局真值，但部署时不需要。

Critic 只在训练时使用，部署时不需要。Critic 可以读取全局真实状态：

- 6 台机器人的位置、速度、朝向；
- 血量、热量、过热、小陀螺；
- 存活、无敌、死亡计时；
- 锁定目标；
- `p_t`、`tau_eff`；
- 每个机器人对每个敌人的累计伤害；
- 每个 agent 的最近一次开火帧实际命中率 `p_final`（环境直接计算，含目标小陀螺；没开火为 0）；`p_t` 同时在 per-agent 状态里；
- 受击提示；
- 比分、时间、占领人数；
- 尸体位置、速度；
- 掩体几何。

Critic 不能读取：

- 未来动作；
- 未来随机数；
- 对手策略网络的内部参数；
- 尚未发生的伤害。

Actor 不能读取：

- 敌人的真实血量；
- 敌人的热量；
- 敌人的 `p_t`；
- 敌人的目标；
- 任何“未来”信息；
- 任何全局真值。

## 14.3 归一化

所有给神经网络的观测都归一化到 0 到 1（或 -1 到 1），但规则本身用绝对单位。

例子：

- 血量：`hp / 325`；
- 热量：`heat / 160`；
- 位置：按场地半长/半宽归一化；
- 速度：`v / 3`；
- 时间：`time / 180`；
- 比分：`score / 90`；
- 距离：`d / 12`；
- 角度：绝对朝向用 `[sin ψ, cos ψ]`，相对方位用 `[sin θ, cos θ]`（`θ = wrap(bearing - ψ)`）；不要用原始弧度或 `θ/π`。

归一化只影响网络输入，不影响伤害、碰撞、热量、比分。

# 15. 动作与观测

这一节是实现接口，不是比赛规则；写在这里是为了让“规则”能直接落地。

## 15.1 动作

每台机器人每帧输出 **6 维**：

| 维度 | 含义 | 范围 |
|---|---|---:|
| 1 | 规范坐标系 x 方向速度意图（红方=世界 +x；蓝方=世界 -x） | [-1, 1] |
| 2 | 规范坐标系 y 方向速度意图（红方=世界 +y；蓝方=世界 -y） | [-1, 1] |
| 3 | 手动云台转向意图 | [-1, 1] |
| 4 | 小陀螺连续目标 | [0, 1] |
| 5 | 目标：0=无，1/2/3=敌人 | {0,1,2,3} |
| 6 | 开火扳机：0=按住不开火，1=开火 | {0,1} |

**瞄准和开火是两条独立逻辑**：

- 第 5 维只负责选目标/锁定；可以保持锁定、让 `p_t` 收敛、预瞄，但**不消耗热量**；
- 第 6 维是独立扳机；只有 `fire=1` 且第 7.4 节全部条件满足时才开火、消耗热量；
- `fire=0` 时可以瞄着等时机、控热、等目标破绽，不需要靠“不锁定/转走”来停火。

- `(1,2)` 是**规范坐标系**速度意图；先裁剪模长到 1，再乘 `v_max_eff`；环境对蓝方乘 `-1` 转回世界（v1.14）；
- `(3)` 只在没有锁定时使用；有锁定时被自动朝向覆盖；
- `(4)` 是连续目标，按 `s_next = clamp(s + clip(u_spin - s, -dt/1.0, +dt/1.0), 0, 1)` 跟随；不是 `>0.5` 的二值判定；
- `(5)` 是 4 类目标（无/敌人1/2/3），取有效类别中模型选中的一项；如果全为 0，视为“无”；
- 正常策略头只会产生一个 1；如果实现收到多个 1，取编号最小的非零项；
- 目标选择必须带 **action mask**：**当前帧**不可见（`p_vis = 0`）或死亡的敌人选项直接 mask 掉；**无敌敌人仍可选中/锁定/预瞄**，只是不能开火命中。
- **上一帧的锁定目标也不例外**：它一旦离开 FOV/被完全遮挡，本帧立即被 mask；
- 如果 3 个敌人全部被 mask，只剩“无”可选；
- 选择被 mask 的敌人不应发生；若实现仍收到，按“无”处理。

这样目标头仍然是 4 类（无/敌人1/敌人2/敌人3），但无效类别不参与采样，减少策略学习空间。

## 15.2 观测（当前实现，140 维）

当前 actor 的观测是 **140 维向量**，拆成 **10 个 token**：

| token | 内容 | 维度 |
|---|---|---:|
| self | 自身状态 + 8 向障碍距离 | 24 + 8 = 32 |
| spawn | 己方启动区相对位置/距离/is_in_spawn | 4 |
| center | 中心占点区相对位置/距离 | 4 |
| 2 × mate | 队友相对/绝对位置、速度、朝向、存活、无敌、复活倒计时 | 2 × 18 |
| 3 × enemy | 敌人相对/绝对位置、速度、朝向、存活、可见性、复活倒计时 | 3 × 17 |
| HUD | 比分、时间、占点人数、存活人数、热量、血量等 | 10 |
| cue | 受击/威胁提示（方向 + 有效性） | 3 |
| **合计** |  | **140** |

- **没有 lidar**；self token 最后 8 维是 8 向墙/掩体 clearance；
- **没有独立 corpse token**；尸体信息并入 mate/enemy token（`alive=0`，保留位置/朝向/复活倒计时）；
- 不可见敌人和无效 cue 用 `src_key_padding_mask` 排除在 attention 和 masked pooling 之外；
- 角度统一用 `[sin θ, cos θ]`，不喂原始角；
- 敌人血量/朝向带噪声；开火帧才使用精确值；敌人热量/目标/真实血量不进入观测；
- 死亡机器人仍生成观测并更新 GRU hidden，但动作被 mask 掉。

观测的具体打包顺序以 `VectorizedMultiAgentSimulator/vmas/scenarios/rm_rules.py` 的 `build_observation()` 为准；旧版 128 点 lidar 段落为历史接口，不再适用。

## 15.3 观测里不能有什么

- 敌人真实血量（只给带噪声的近似值）；
- 敌人真实朝向（只给 ±5° 噪声值；开火帧精确）；
- 敌人热量；
- 敌人 `p_t`；
- 敌人目标（可选“开火后知道目标”默认关闭）；
- 尸体速度（位置、朝向、复活倒计时是允许的；v1.5）；
- 未来的随机数；
- 全局真值。

如果实现里为了方便把真值塞进 actor 观测，规则就被破坏了。

# 16. 边界情况逐条说明

这一节把容易扯皮的情况写死。

## 16.1 目标在开火瞬间死亡

本帧伤害同时结算。目标死亡不影响本帧已经算出的伤害；但目标死亡后，下一帧不能再选它。

## 16.2 多射手同帧击杀

按 10.3 节：原始期望伤害最大者拿击杀分；相同取编号小。

## 16.3 溢出伤害

不计入 `total_damage`，但击杀算。

## 16.4 目标离开 FOV

锁定立即丢失；本帧不 fire；`p_t = 0`；下一帧重新选。

## 16.5 目标被完全遮挡

锁定立即丢失；本帧不 fire；`p_t = 0`。

## 16.6 目标部分遮挡

目标仍可见；`p_vis` 按可见弧比例；可以锁定、可以打；命中率乘 `p_vis`。

## 16.7 切换目标

`p_t = 0`；`tau_eff` 重新按新目标当前小陀螺决定；云台开始转向新目标。

## 16.8 小陀螺中途开始

如果已经锁定：

- `p_t` 不重置；
- `tau_eff` 随 `s_target` 增大而连续变长；
- 最终命中率乘 `1-0.4s_target`；
- 目标转得越深，乘得越多。

如果还没锁定：

- 新锁定从 `p_t = 0` 开始；
- `tau_eff` 用锁定那一刻的 `s_target` 连续计算：`tau_eff = tau × (1 + 0.5 × s_target)`；
- 不是阶跃到 1.5 倍。

## 16.9 小陀螺中途停止

- `m_spin` 回到 1；
- `p_t` 继续；
- `tau_eff` 随 `s_target` 减小而变短，回到 `0.4 s`。

## 16.10 双方都小陀螺

- 各自入射乘 0.6；
- 各自出射上限乘 0.9；
- 各自瞄准对方 `tau_eff` 最多 1.5 倍；
- 不叠乘 2.25。

## 16.11 热量刚好到 160

- 本帧仍然造成伤害；
- 然后进入过热；
- 下一帧不能开火；
- 热量降到 0 解锁。

## 16.12 过热期间目标死亡

- 锁定丢失；
- `p_t = 0`；
- 热量继续冷却；
- 解锁后需要重新锁定、重新收敛。

## 16.13 死亡瞬间正在开火

本帧伤害先结算，然后死亡。死亡机器人本帧的伤害有效。

## 16.14 复活瞬间被瞄准

复活后有 3 s 无敌；不能被伤害、不能被开火命中，但可以被锁定和预瞄；3 s 后才可以被打。

## 16.15 复活位置在掩体里

原地复活、不位移；下一帧做位置修正；复活速度为 0，不满足判负速度阈值，所以不判负、不扣血。

## 16.16 复活位置和别的机器人重叠

原地复活、不位移；下一帧做无伤害的位置分离；复活速度为 0，不满足判负速度阈值，所以不判负、不扣血。不会回己方启动区。

## 16.17 无敌期间回血

可以；按 81.25/s；可以回满；无敌结束不强制重置血量。

## 16.18 无敌期间撞人

无敌机器人是物理实体：

- 会推人、会被推、会挡路、会挡视线；
- 碰撞照常做位置分离和速度修正；
- **碰撞判负也照常做，无敌不豁免**；
- 它高速撞活人，按主动方判它负；
- 别人高速撞它，按主动方判别人负；
- 它高速撞尸体，按它自己的法向速度判；尸体无主动方资格；
- 它高速撞墙/掩体，照样判负；
- 它被推着撞墙/掩体，按它自己的法向速度判，不豁免。

## 16.19 尸体挡视线

挡；尸体是实体；但不能被选为目标。

## 16.20 尸体被推入墙

只做位置修正；不判负；尸体所属队伍不因尸体撞墙而输。

## 16.21 活人高速撞尸体

活人法向速度 >= 2.0 m/s：活人全队负；如果活人与尸体同队，就是该队负（队友尸体不豁免）；只有敌方撞尸体时，尸体所属队伍才不输。

活人法向速度 < 2.0 m/s：做等质量非弹性碰撞（位置分离 + 法向速度取均值）；不扣血、不判负；尸体之后继续每帧减速 5.0 m/s²。

## 16.22 被推入墙

不豁免；被推者撞墙法向速度 >= 2.5 时，被推者队伍负；推人者如果机器人碰撞 >= 2.0，也负；可能双方都负，判平局。

## 16.23 队友高速相撞

判负；主动方队伍负；同责该队负。

## 16.24 同一帧双方都犯规

平局；双方都算输；训练时双方每台机器人终端奖励 -10。

## 16.25 同一帧双方都到 90

平局；双方每台机器人终端奖励 +2。

## 16.26 时间到比分相同

按总伤害、总血量、平局。

## 16.27 判负与时间同帧

判负优先；时间不再结算。

## 16.28 判负与开火同帧

碰撞先判；判负后本帧不再开火。

## 16.29 低血量回血

回血可以超过 65，最高 325；没有“只能回到 65”的限制。

## 16.30 尸体滑动中复活计时

尸体继续滑；复活位置取 5.0 s 到点那一帧复活结算时尸体所在的位置。

## 16.31 尸体速度很小

小于 0.01 m/s 直接置 0，避免抖动。

## 16.32 多起碰撞同帧

逐对检查；只要有任何判负，本局结束；如果涉及两个队伍，平局；只涉及一个队伍，该队负。

## 16.33 机器人被墙和机器人同时撞

先按碰撞规则分别算；只要有一个判负，本局结束；判责按 12.9。

## 16.34 目标在 12 m 外

目标可见，但 `d >= 12 m` 时 `p_dist = 0`，`p_base = 0`，`p_ideal = 0`，最终伤害为 0。

可以锁定，但因为开火条件要求 `p_dist > 0`，所以不会开火、不会消耗射击热量、不会造成伤害。锁定只影响云台自动朝向和 `p_t` 状态；`p_t` 会保持 0。

## 16.35 目标在 12 m 边界

`d = 12.0`：`p_dist = 0`，不能造成伤害；`d = 11.999`：可以，但命中率极低。

## 16.36 可见弧为 0

完全不可见；不能锁定；不能开火；不提供敌人信息。

## 16.37 可见弧很小

可以锁定；可以开火；`p_vis` 很小；伤害极低；仍然消耗热量。

## 16.38 锁定目标在转向后离开 90°

锁定丢失；本帧不 fire；`p_t = 0`。

## 16.39 锁定目标在转向后进入 1°

如果目标仍可见，角度 <1°，开火；命中率按当前 `p_t`。

## 16.40 热量降到 0 的那一帧

先冷却到 0，解除过热；如果本帧有锁定、角度 <1°、热量 <160，可以开火；开火后热量 +15。

# 19. 训练与评测预设

| 预设 | 时间 | 目标分 | 用途 |
|---|---:|---:|---|
| 训练 | 180 s | 90 | 与评测一致，避免 train/eval 分布不同 |

控制频率 10 Hz。动作每帧一次。

## 19.1 训练奖励表（不是比赛规则）

这张表只用于训练，不是裁判规则；比赛胜负只看第 13 节。终端奖励按**每台机器人**计。

| 事件 | 每台机器人奖励 | 说明 |
|---|---:|---|
| 正常获胜 | `+6 + 3 × 剩余时间比例 + 3 × 分差/90` | 剩余时间比例 = `s.time/180`；分差最多 +3 |
| 正常失败 | `-6` | 固定，不再按分差连续 |
| 碰撞犯规（单方） | `-10 - 3 × severity` | 只罚实际肇事 agent；severity = `clamp((impact-2)/(6-2),0,1)`；对手/队友 0 |
| 推墙/推人（单方） | 主动方 `-10`；队友 `-0.5`；对手 `0` | 对手不加分；双方推时双方主动方都 -10 |
| 普通平局 | `0` | 时间到 tiebreak 相同 |
| 双方同帧到 90 | `+2` | 双方都算“双方到 90”平局 |
| 双方同帧严重犯规 | `-10` | 双方都算输 |
| 空局（10 s 无事件） | 最多 `-5` | 按障碍/出生点/队伍中心/移动四项折扣，见 13.11 |
| 击杀比分 | 队伍 `+10` | 每次击杀只加一次；按 10.3 选击杀者 |
| 占点比分 | 每帧 `0.1 × 净占点人数` | 净人数 = 红圈内人数 − 蓝圈内人数 |

**训练 dense（每台每帧，不是比赛规则）**：

- 占点比分：`0.01 × Δscore`（击杀分不在其中，单独分配）；
- 命中：`0.05 × last_hit_damage / 325`；
- 击杀奖励池：每次击杀 `0.3`，按各 attacker 对目标的累计伤害占比分配；
- 中心接近：`0.003 × exp(-d²/(2×1.5²))`，仅圈外、存活；
- 中心 potential：`0.02 × (上一帧 d_center − 当前 d_center)`，仅存活；
- 圈内驻留：每台存活、非无敌机器人每帧 `+0.002`；
- 存活：`0.00005 × hp/hp_max / 帧`；
- 低血回己方启动区：`0.0005 × exp(-d_home²/(2×2²))`，仅 `hp < 50%` 且存活；
- 满血在己方启动区朝出口移动：`0.002 × 归一化出口速度`；
- 死亡瞬间：`-0.2` dense；死亡期间（非死亡帧）dense = 0；
- 墙/掩体冲击：首次接触 `0.02 × 法向推速/v_max`；持续接触按接触时长 `0.001→0.005` ramp，并乘 `(0.2+0.8×推速比例)`；
- 机器人/尸体冲击：首次接触 `0.3 × 法向相对速度/(2×v_max)`，双方各承担一半；
- 贴人：0.65 m 内双方扣，主动 60%/被动 40%，`0.0025/帧` 起、2 s 内最多翻倍；
- 持续推人：`0.001 + 0.004×t/2 s`，随推速缩放；
- 开火热量：每发 `-0.001`；
- 反蹲：出生区/中心外长时间静止，按时间 ramp 扣分（低血和目标锁定豁免）。

具体的缩放、折扣和实现顺序以 `rm_rules.py` 的 `_finalize_rewards()` 与 `rm_config.py` 为准；旧版表格中的 `+2 / -2`、`+20`、`0.6` 击杀池、旧版贴人/接触数值均已不再使用。

## 19.2 随机初始化课程（训练用，不是比赛规则）

为了加速早期演化，训练可以随机初始化局面，而不是每局都从固定出生位开始。**这只改变训练分布，不改变比赛规则**；评测和最终训练必须回到官方固定出生。

建议配比：

- **50% 镜像对称随机**：先抽样红方 3 台的位置/朝向/血量，再按 180° 镜像生成蓝方；时间、比分双方共享。保证自博弈公平，critic 学到的是对称局面。
- **50% 非对称随机**：红蓝独立抽样，允许一方位置更好、血量更高、时间更紧。目的是让 critic 直接见到“必胜/必败局面”，加速价值函数学习；策略也会学到如何在劣势下翻盘或守住优势。

随机范围（建议初版）：

| 项 | 范围 |
|---|---|
| 位置 | 全场地合法点，圆心离墙/掩体 ≥ 0.35 m；机器人之间 ≥ 1.0 m；不生成在对方启动区内 |
| 朝向 | `U[-180°, 180°)` |
| 剩余时间 | `U[30, 180]` s |
| 血量 | `U[65, 325]` |
| 小陀螺 | `U[0, 0.5]` |
| 热量 | `U[0, 80]`，不直接生成过热状态 |
| 比分 | 初版不随机；后续可加 `U[0, 150]` 教逆风/顺风局 |

- 随机开局**不采样死亡/复活中/无敌状态**：6 台全部 `alive=true`，`hp` 65–325，`respawn_timer=0`，`invuln=false`，`target=0`，`overheated=false`。尸体只在局中死亡后出现，不参与随机初始化。

课程退火：

1. **阶段 A**：全图随机 + 非对称 50%，快速学战斗、控热、占点、复活；
2. **阶段 B**：位置收窄到出生区附近，血量/时间收窄，非对称比例降到 20~30%；
3. **阶段 C**：官方固定出生、325 血、0 热、0 自旋、180 s；保留 10~20% 随机局做鲁棒性，但**评测始终用官方分布**。

**v1.8 实现（线性 fixed-start 课程）**：

- `init_mode=curriculum`；
- 每个 reset 按 `p_fixed` 选择官方固定开局，否则走随机开局；
- `p_fixed` 从 `fixed_prob_start` 线性升到 `fixed_prob_end`，跨 `curriculum_steps` 个 env step；
- 随机部分内部仍 50% symmetric + 50% asymmetric（`rsi_symmetric_prob`）；
- 推荐 `fixed_prob_start=0.0`、`fixed_prob_end=1.0`、`curriculum_steps=50_000_000`；
- 评测进程强制 `init_mode=fixed`（`RM_EVAL=1`），不吃课程比例。

注意：

- 随机初始化必须做合法性拒绝采样，不能生成在掩体里、墙外、或与别人重叠；
- 随机局和官方局要分开统计胜率，不能只看随机局指标；
- GRU 的 hidden state 在随机局开始时清零是允许的；但正式训练要保留一定比例的“整局固定出生”rollout，避免模型只会打局部遭遇战、忘记 180 s 的长程节奏；
- 非对称随机只用于训练；如果发现策略开始利用“随机到对方没血”这种局面，降低非对称比例或加回对称混合。

# 20. 实现验收清单

1. 6 台机器人固定出生，不重叠，红蓝 180° 对称。

6. 时间到：比分 → 伤害 → 总血量 → 平局。
7. 墙/掩体法向速度 2.5 判负；机器人相对法向 2.0 判负。
8. 低于阈值碰撞只推开，不扣血。
9. 队友高速相撞判负。
10. 双方同责平局。
11. 无敌机器人是物理实体；碰撞判负照常，无敌不豁免；它高速撞人/墙/掩体照样输。

13. 活人高速撞尸体，活人判负。
14. 死亡 5.0 s 复活，位置为复活结算时尸体所在位置。
15. 复活 65 血，3 s 无敌，可回血，不能开火；云台朝向继承死亡帧朝向（v1.3；不随机）；无敌结束同一帧 heat=160、overheated=true。
16. 回血 81.25/s，可移动可开火，受击不中断。
17. 热量 160 上限，每帧 +15 / -2；从 0 开始第 13 个射击帧（1.3 s）过热，8 s 解锁。
18. 过热期间不能开火，但可以锁定/转向/占点/回血。

23. 受击提示只持续 1 帧，±45°，无距离。
24. 可见弧最大 120°（贴住）到 180°（远）；无遮挡 p_vis=1。
25. FOV 90；瞄准时其他敌人 80；锁定目标 90。
26. 选择不可见敌人视为不锁定，不报错；**上一帧的锁定目标一旦离开 FOV，同一帧立即 mask**，不能对墙/掩体保持锁定。
27. 锁定后云台每帧最多 27°，不超调。
28. 开火角 <1°；没有单独 fire 键。
29. 目标切换后 p_t=0。
30. 12 m 外可看见但不能造成伤害，也不耗热。
31. 推墙/掩体连续 1.0 s 或推人/尸体连续 0.5 s 触发对应终局；主动方 -10，队友 -0.5，对手 0。
32. 空局 10 s 终止，outcome 23；净占点人数计分。
31. 尸体速度 <0.01 置 0。
32. 复活严格使用尸体位置，不搜索、不位移；重叠下一帧分离。
33. 无敌结束不强制重置血量。
34. 归一化只影响观测，不影响规则。
35. Actor 不读敌人真实血量/热量/p_t。
36. Critic 能读全局真值，但不读未来。
37. 击杀到 90 立即结束，不再结算占点；双方同帧到 90 平局。
38. 热量降到 0 的同一帧解除过热，并且可以开火。
39. 复活是同一实体从 DEAD 切到 INVULNERABLE，位置不变，不搜索、不位移；重叠下一帧分离。
40. 尸体是同一实体的 DEAD 状态；与活人做等质量非弹性碰撞，但每帧 5.0 m/s² 减速；活人撞尸体按活人法向速度判，尸体无主动方资格；无敌单位正常推挤，碰撞判负照常。
41. 受击提示取本帧原始期望伤害最大的攻击者，只给方向、不给编号。
42. 死亡机器人仍生成观测并更新记忆，但动作全部 mask；云台冻结在死亡朝向。
43. 尸体不可选；位置（相对+绝对）、朝向、复活倒计时可见（队友始终，敌人需 FOV/可见弧）；不提供血量/热量/目标/开火/速度。
44. `tau_eff = 0.4 × (1 + 0.5 × s_target)` 每帧连续计算，不阶跃。
45. 无敌机器人自己可以预瞄；别人不能选中它，所以别人对它的 `p_t/tau_eff` 不增加。
46. 对方启动区每帧扣 8.125 HP，无击杀者；无敌不受；可致死。
47. 敌方云台 ±5° 噪声，开火帧精确；可见敌人有是否开火标志。
48. 目标选择 mask 掉当前帧不可见/死亡选项；**无敌敌人仍可选/锁定/预瞄**；上一帧锁定目标也不例外，离开 FOV 同一帧立即 mask）；完整 64 点可见弧只在开火时算。
